LESSON 620.2.1 · BOARD CONFIGURATION

選擇 Scrum、Kanban 與 Kanban backlog

先辨認團隊承諾工作的節奏，再選 board；不要用產品名稱替團隊決定流程。

情境理解＋實作驗證官方來源對照原創練習與解析
頁面目錄
從工作情境判斷 board 類型三種選擇，各解決不同問題先作判斷，再看建議Demo lab：同一批工作，用不同節奏觀察看不到預期功能時五題選型練習官方來源與閱讀範圍
考綱沿用 project／issue／issue type／rule；現行文件可能稱 space／work item／work type／flow。依功能辨認入口；先確認管理方式、權限與方案。下列互動均為本機模擬，實作步驟只供隔離的 demo site 跟做。

考綱目標：Given a scenario, recommend an appropriate board type (Scrum, Kanban, Kanban with backlog)

從工作情境判斷 board 類型

訂餐網站有兩組人：產品開發組每兩週交付一批功能，維運組每天處理不定時進來的問題。兩組都能把工作排成 To Do、In Progress、Done，但承諾工作的方法不同。完成本課後，你應能解釋 sprint 與持續拉取工作的差別，並判斷何時需要獨立 backlog。

Board 是 issue 的工作視圖；project 是 issue 所屬的容器。新增另一塊 board 不會複製每一筆 issue，也不代表必須重建 project。Company-managed board 可從 saved filter 建立，資料範圍由 filter 決定。

設定板的權限：目前官方文件列出 board administrator，或 board 所在 location project／space 的 administrator，可配置板設定。Jira admin 的頭銜本身不能用來推定已取得該 saved filter 與來源 project 的資料存取；請分別確認 filter 分享、Browse 與 issue security。

三種選擇，各解決不同問題

選項工作承諾與視圖適合案例選擇前要想清楚
ScrumBacklog 中規劃未來工作；選一批 issue 加入 sprint，開始後在 Active sprints 處理。兩週一次交付購物車功能，希望比較每次承諾與完成量。需要 sprint 規劃、開始與完成；看到空 board 可能只是尚未開始 sprint。
Kanban工作持續流動；團隊有容量才從待辦拉進進行中，沒有必要以 sprint 作為主要節奏。每天不同數量的維運修復、緊急請求。應定義工作進入條件及 WIP 提醒；Kanban 不等於沒有優先順序。
Kanban with backlog仍是 Kanban board，另把尚未準備執行的工作放進獨立 backlog。持續接需求但待評估清單已達數百筆，執行板只想留 ready 與進行中。Backlog 功能不會自動加入 Scrum sprint 承諾；必須配置 backlog statuses。

Kanban with backlog 不是第三種管理方式；它是在 Kanban 上啟用 backlog。Company-managed 可到 Board settings → Layout → Columns，將適當 status 放進 Kanban backlog 區域。Team-managed 的 backlog／sprints 由 project 的 Features 等入口管理，不能照搬 company-managed 的設定選單。

先作判斷，再看建議

情境一：團隊每日接件，但主管希望每週看一次進度

建議 Kanban。每週開會不代表每週承諾固定 sprint 範圍；觀察工作實際如何進來、如何拉取，才是選板依據。

情境二：待辦太多，工程師很難找出已準備好可做的工作

建議 Kanban with backlog，把待評估與 ready 分開。只有當團隊也需要固定期間承諾、sprint 規劃與報表時，才進一步考慮 Scrum。

情境三：共同產品每兩週選一批功能，期末檢查完成量

建議 Scrum。不要只看是否有「Done」欄，應看是否需要 sprint 與承諾／交付的比較。估算與報表的連動見 620.2.5。

Demo lab：同一批工作，用不同節奏觀察

前置：在 demo site 使用獨立 company-managed software project，例如 BDLAB；若沒有建立權限，請使用已獲准的測試 project。以該 project 的 Browse 與管理權限操作，勿使用正式團隊的 board。以下 key 只是範例，需換成你的 key。

  1. 建立三筆 Task：「規劃餐點搜尋」「實作餐點搜尋」「修正測試提示」。保留在初始 status，並記下 key。
  2. 在進階搜尋執行 project = BDLAB ORDER BY Rank ASC，另存為「ACP620 Board Lab」。
  3. 由 All boards → Create board → Scrum → Board from an existing Saved Filter，建立「ACP620 Scrum Lab」。預期三筆工作可在 backlog 找到；尚未加入並開始 sprint 時，不應期待 Active sprints 自動顯示它們。
  4. 使用同一 filter 再建立「ACP620 Kanban Lab」。檢查所有三筆 status 都映射到 columns；預期可在相應欄位看到工作。
  5. 只在測試 Kanban board 的 Columns 將一個待辦 status 指派到 Kanban backlog。預期該 status 的工作改由 backlog 管理；並未被刪除。把一筆工作移至代表 ready 的狀態後，觀察執行板。
  6. 完成後保留有清楚 Lab 名稱的板與 filter 作後續章節練習；不必刪除 project 或影響正式 sprint。

驗收：你能指出三筆 issue 在兩塊板中是同一資料，並用「是否以 sprint 承諾工作」「是否需要獨立待辦整理區」說明選擇。

看不到預期功能時

看不到 Create board 先確認所在入口及存取權限；team-managed 不支援直接在 project 裡新增額外 board，但可從 saved filter 建立 company-managed board 讀取該 project 的工作。看不到 Kanban 卡片，先查 status mapping；看不到 Scrum 卡片，再查 sprint 是否開始。不要為了讓卡片出現而把工作一律改成 In Progress。完整查核順序見 620.2.7。

五題選型練習

以下皆為原創單選情境題，非官方考古題。先選答案，再展開解析；每題只有一個最佳答案。

1．兩週規劃固定一批功能並比較交付量，哪種最適合？

  1. Scrum
  2. Kanban，因為有 Done 欄
  3. 只改 project 名稱
  4. 只加 Labels
查看答案與四個選項解析

答案：A

A：Scrum 直接支援 sprint 規劃與交付檢視。

B：Done 欄不是 sprint 的替代。

C：名稱不會提供 sprint 功能。

D：Labels 分類工作，不建立交付節奏。

English version

A team plans a fixed set of features every two weeks and compares delivery with its commitment. Which board fits best?

  1. Scrum
  2. Kanban because it has a Done column
  3. Rename the project
  4. Add labels
Answer and explanations

Answer: A

A: Scrum directly supports sprint planning and delivery review.

B: A Done column does not replace a sprint.

C: A name does not provide sprint functionality.

D: Labels classify work; they do not define the delivery cadence.

2．每日不定量接件，待評估清單很長，最佳起點？

  1. Scrum，因為工作很多
  2. Kanban with backlog
  3. 刪除未完成工作
  4. 每人建一個 project
查看答案與四個選項解析

答案：B

A：數量多本身不構成 sprint 需求。

B：保留持續流動並提供獨立 backlog。

C：刪除會失去需求，不是管理待辦的方法。

D：分拆容器增加管理成本，沒有解決 ready 與待評估混雜。

English version

Requests arrive continuously and the unassessed queue is long. What is a suitable starting point?

  1. Scrum because there are many items
  2. Kanban with backlog
  3. Delete unfinished work
  4. Create a project for each person
Answer and explanations

Answer: B

A: Volume alone does not require sprints.

B: This retains continuous flow while separating backlog preparation.

C: Deletion loses requirements instead of organizing them.

D: Separate containers do not distinguish ready work from unassessed work.

3．建立第二塊 board 讀取同一 filter，會發生什麼？

  1. 自動複製所有 issue
  2. 自動建立新 workflow
  3. 不同視圖讀取同一批 issue
  4. 原 board 失效
查看答案與四個選項解析

答案：C

A：Board 不會自動複製 issue。

B：建立 board 不等於建立 workflow。

C：同一 issue 的狀態異動會反映於所有符合條件的視圖。

D：兩塊 board 可並存。

English version

A second board uses the same saved filter. What happens?

  1. Every issue is copied
  2. A new workflow is created
  3. Different views display the same issues
  4. The original board stops working
Answer and explanations

Answer: C

A: A board does not automatically copy issues.

B: Creating a board is not creating a workflow.

C: Changes to the same issue appear in all applicable views.

D: Both boards can coexist.

4．Scrum board 空白但 backlog 有工作，首先檢查？

  1. 是否有 active sprint 且工作在其中
  2. 是否所有人都是 Jira admin
  3. 是否每筆都已估時
  4. 是否更換 project key
查看答案與四個選項解析

答案：A

A：Active sprints 視圖取決於 sprint。

B：一般成員不需 Jira admin 才能看板。

C：未估時不必然被排除。

D：Key 不會開始 sprint。

English version

A Scrum board is empty but its backlog has work. What should you check first?

  1. Whether an active sprint contains the work
  2. Whether everyone is a Jira admin
  3. Whether every issue has an estimate
  4. Whether the project key should change
Answer and explanations

Answer: A

A: The Active sprints view depends on sprint membership and state.

B: Ordinary members do not need Jira admin privileges to view a board.

C: An unestimated issue is not necessarily excluded.

D: Changing a key does not start a sprint.

5．Kanban backlog 的正確理解？

  1. 一定有兩週 sprint
  2. 與 issue 資料庫分離
  3. 啟用後自動完成工作
  4. 把待處理工作整理到獨立區域
查看答案與四個選項解析

答案：D

A：啟用 backlog 不會建立 sprint 節奏。

B：仍是原本 issue。

C：完成仍由 workflow 與完成規則決定。

D：它讓執行板較聚焦，保留可排序的待辦區。

English version

What does a Kanban backlog provide?

  1. A mandatory two-week sprint
  2. A separate issue database
  3. Automatic completion
  4. A separate area for organizing pending work
Answer and explanations

Answer: D

A: Enabling a backlog does not establish a sprint cadence.

B: It still uses the original issues.

C: Completion still depends on workflow and completion rules.

D: It keeps the execution board focused while retaining a ranked preparation area.
