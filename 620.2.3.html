LESSON 620.2.3 · BOARD CONFIGURATION

將 workflow statuses 映射到 board columns

區分資料的狀態、畫面的欄位與合法 transition，才能解釋卡片消失、移不動和 sprint 未完成。

考綱目標：Configure board columns to match a workflow process

欄位是視覺分組，status 是 issue 資料

訂餐網站的 workflow 有 Open、Developing、Review、Closed。團隊想畫成 To Do、Doing、Done 三欄，可以把 Developing 與 Review 都放在 Doing。不必為了少一欄就刪掉審查流程。反過來，新增 Review 欄也不保證 workflow 自動增加可用 transition。

映射與 transition 的差異

在 company-managed board 的 Board settings → Layout → Columns，將 status 卡片拖到 column。多個 statuses 可映射到同一欄；沒有映射的 status 放在 Unmapped 區。卡片雖符合 board filter，若 status 未映射，仍可能不出現在板上。

移動 status 的「映射」是在改呈現方式；拖 issue 卡片跨欄，通常是在執行 workflow transition。若目的欄有多個可用 statuses，介面可能讓你選目標 status。若 workflow 沒有合法路徑，或使用者不符 transition 的權限／condition，新增欄位不會繞過限制。

操作影響應驗證
新增 column增加視覺分組；simplified workflow 可能同時建立同名 status。先確認是否 simplified workflow，不要把此副作用當成所有 workflow 都有。
刪除 column該欄 statuses 回到 Unmapped；issue 不會因此刪除。原 status 的卡片可能從板消失，需重新映射。
改 column 名稱改畫面標題。不應推定 workflow status 已同時改名。
重新排列 columns改流程呈現與最右完成欄。檢查各完成 statuses 是否仍在最右欄。
刪除 status屬於 workflow 層次的操作，有額外權限與使用中限制。與刪欄不同；一般 workflow 需 Jira admin 在 workflow editor 處理。

TMP transition 限制的現行範圍：官方 Restrict who can move a work item 已列 assignee、reporter、指定使用者、role、group 與特定 permissions。不要再用舊畫面斷言「只能選人與 role」。但直接指定 group，與讀取某個 group custom field 裡的值作為允許名單，是兩種能力；後者不能從前者推得。參考 官方 workflow rules。

完成是看最右欄，不是只看 Done 字樣

對 board 的 sprint 完成判斷，Jira 將最右側 column 的工作視為完成。假設 Closed 映射在倒數第二欄，而最右欄叫 Archived，即使 Closed 的 status category 是 Done，也不能只靠名稱或類別推論本板的 sprint 完成量。

團隊應先約定哪些 statuses 代表本流程終點，再把它們映射到最右欄。例如 Canceled 是否算已終結，需要業務定義；不能因官方範例出現 Blocked 就把所有 blocked 工作都視為完成。Resolution 是另一個欄位，許多搜尋與報表會使用它；把 issue 拖進最右欄，不保證任何 workflow 都會替你正確設定 Resolution。

四種「完成」訊號要分開讀

概念代表什麼不保證什麼
Status目前 workflow 節點，例如 Closed、Canceled。名稱含 Done 不代表所有報表都視為完成。
Status category每個 status 所屬 To do／In progress／Done 大類。不是這塊 board 的 column mapping。
最右 columnScrum sprint 與多種 agile reports 判讀完成工作時的重要依據。不能直接代替 Kanban Hide completed work 的判斷。
Resolutionissue 結束的結果欄位，例如 Fixed；未填表示 unresolved。進入某個完成欄不保證任意 workflow 都會設定它；重新開啟也須處理清除。

特別注意：官方 Cloud KB 指出，Kanban 的 Hide completed work 以 Done status category 判斷待隱藏工作，計時還受最後更新影響；Scrum sprint 完成則看最右欄。因此同一 issue 在某個報表與隱藏機制中可能有不同表現。檢查目標功能的規則，不能只套一句「最右欄等於一切完成」。

短練習：status category 是 Done，但映射到 Scrum 倒數第二欄；Resolution 也空白。三件事能互相抵銷嗎？

不能。它可能不算該 Scrum board 的完成工作，而 Resolution-based 搜尋仍視為 unresolved。應按實際完成流程修正 mapping／workflow，不是改一個名稱就完成全部設定。

刪掉完成欄，不能當成清理卡片的方法

原創例：板上剩「待辦」與「驗收」，而驗收成為最右欄。結束 sprint 時，映射在驗收欄的工作會依該板被判定為完成；這不代表它真的通過業務驗收。原先完成狀態若變成 unmapped，也不會因為名字叫 Done 或已有 Resolution 就取得最右欄判定。

另分清被移回 backlog 的歸屬與在目前 backlog 視圖看得到：未映射狀態的工作可能需要移至後續 sprint 或 backlog，但目前 board 的映射仍可能讓它不可見。題目把兩者都簡稱「在 backlog」時，先檢查它問的是資料去向還是畫面可見性。不要只看到選項前半句正確，就忽略後半句。

WIP constraints 是警示，不是硬限制

Columns 可選 Work item count 或 excluding subtasks，並為各欄設定 minimum／maximum。超過 maximum 時出現紅色警示，低於 minimum 時出現黃色警示。這是提醒團隊檢查瓶頸，不會因 maximum = 3 就禁止第 4 筆卡片進入。

計數包含被 quick filter 隱藏的工作。例如 Doing 實際 5 筆，套用「我的工作」只見 2 筆，maximum = 3 仍可能紅色。這能避免每個人都覺得自己的 WIP 很低，卻忽略團隊總量。

預測：maximum = 2，已有 2 筆，再移入一筆會如何？

若 transition 本身允許，移入可成功；欄位以警示提示總量達 3。若移不進去，應另外查 workflow／權限，不應直接歸因於 WIP constraint。

Demo lab：安全重現 Unmapped

  1. 在「ACP620 Kanban Lab」確認一筆測試 issue 的 status，記下目前 mapping；不要在正式共用 workflow 刪 status。
  2. 新增「Review view」column。若使用非 simplified workflow，先將現有測試 status 映射到此欄；沒有適合 status 時改用既有欄做示範，不為練習擅改 workflow。
  3. 確認卡片出現在此欄，接著只刪除這個 column。預期該 status 回到 Unmapped，卡片不再在板上顯示。
  4. 直接開 issue key 或以 JQL 搜尋；預期 issue 仍存在且 status 未因刪 column 改變。
  5. 把該 status 重新映射回原 column。預期卡片恢復顯示。
  6. 在 Doing 設 maximum = 1，放入兩筆符合 transition 的測試工作；預期警示而非拒絕。完成後回復原 mapping 與 constraint。

驗收：能解釋「filter 找得到、board 看不到」，並證明刪 column 與刪 issue 不同。若沒權限修改 Columns，請記錄缺少的角色，不以更改正式權限完成練習。

五題 mapping 判斷

以下皆為原創單選情境題，非官方考古題。先選答案，再展開解析；每題只有一個最佳答案。

1．刪除 company-managed board 的 column，映射的 status 通常去哪？

  1. 隨所有 issue 永久刪除
  2. Unmapped
  3. 自動改成 Done
  4. 移到另一個 project
查看答案與四個選項解析

答案：B

A：刪欄不會刪 issue。

B：官方說明會回到 Unmapped。

C：不會自動完成。

D：Column 不決定 project 歸屬。

English version

When a company-managed board column is deleted, what normally happens to its mapped statuses?

  1. They and all issues are deleted permanently
  2. They return to Unmapped
  3. They automatically become Done
  4. They move to another project
Answer and explanations

Answer: B

A: Deleting a column does not delete issues.

B: The documented behavior is to move statuses back to Unmapped.

C: Deletion does not complete the work.

D: Columns do not determine project ownership.

2．兩個 status 要在同一欄顯示，應如何？

  1. 合併所有 workflow
  2. 只能刪一個 status
  3. 兩者映射到同一 column
  4. 複製 board
查看答案與四個選項解析

答案：C

A：不必為呈現改造所有 workflow。

B：支援多 status 對一欄。

C：是原生 mapping 用法。

D：複製板不是解法。

English version

How can two statuses appear in the same column?

  1. Merge all workflows
  2. Delete one status
  3. Map both to one column
  4. Copy the board
Answer and explanations

Answer: C

A: Presentation does not require rebuilding every workflow.

B: Multiple statuses can map to one column.

C: This is a native mapping capability.

D: Copying a board does not solve the mapping requirement.

3．Status 叫 Done，但在倒數第二欄，sprint 完成判斷應看？

  1. 最右欄映射
  2. 只看 status 英文
  3. 只看卡片綠色
  4. 只看 assignee
查看答案與四個選項解析

答案：A

A：最右 column 是板的完成依據。

B：名稱不足以證明完成。

C：顏色可能來自不同設定。

D：負責人不決定完成。

English version

A status named Done maps to the second-to-last column. What controls the board’s sprint completion interpretation?

  1. The right-most column mapping
  2. Only the status name
  3. Only a green card color
  4. Only the assignee
Answer and explanations

Answer: A

A: The right-most column defines completed work for the board.

B: The name alone is insufficient.

C: Colors can come from unrelated settings.

D: Ownership does not define completion.

4．Maximum 3，第四筆仍能移入，代表？

  1. Jira 故障
  2. Filter 已壞
  3. 一定缺少 Browse
  4. Constraint 是視覺警示
查看答案與四個選項解析

答案：D

A：這符合設計。

B：與 filter 是否有效不同。

C：能移入不代表 Browse 有問題。

D：不是 workflow validator 或禁止規則。

English version

A column maximum is three, but a fourth issue can enter. What does that mean?

  1. Jira is broken
  2. The filter is invalid
  3. Browse permission must be missing
  4. The constraint is a visual warning
Answer and explanations

Answer: D

A: This is expected behavior.

B: It does not imply an invalid filter.

C: The ability to enter a column does not show a Browse problem.

D: The constraint is not a workflow validator or hard prohibition.

5．新增 Review 欄後仍不能把卡片移入，優先檢查？

  1. 換顏色
  2. 可用 status、transition 與權限
  3. 改 working days
  4. 增加 card fields
查看答案與四個選項解析

答案：B

A：顏色不建立 transition。

B：映射與 workflow 可執行性都必要。

C：工作日影響報表，不提供 transition。

D：卡片欄位只是呈現資訊。

English version

A new Review column exists but a card cannot move into it. What should you check?

  1. Change its color
  2. Available statuses, transitions, and permissions
  3. Change working days
  4. Add card fields
Answer and explanations

Answer: B

A: Color does not create transitions.

B: Both mapping and executable workflow transitions matter.

C: Working days affect reporting, not transition availability.

D: Card fields only present information.
