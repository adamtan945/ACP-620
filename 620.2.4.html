把需求轉為 board filter、sub-filter、quick filter

考綱目標：Translate requirements into board filters, sub-filters, and quick filters

先問：這個條件應該讓誰、在何時套用？

產品負責人說：「整塊板只看訂餐專案；已發版工作不用堆在 Kanban；開會時可以切換只看我的 Bug。」這不是一條查詢就該全部寫在 base filter。專案是長期範圍；發版是 Kanban 工作流規則；「我的 Bug」則是可暫時切換的焦點。

三層條件比較

設定功能原創範例重要影響
Board saved filter決定候選資料，Scrum／Kanban 都使用。project = BDLAB ORDER BY Rank ASC改 shared filter 可影響其他 board、gadget、訂閱。
Kanban sub-filter再縮小 Kanban 執行板範圍。fixVersion in unreleasedVersions() OR fixVersion is EMPTY範例保留未發版或無版本工作；請檢查你板上的實際值，勿推定每板必定有此預設。
Quick filter從符合基礎範圍的工作中選擇焦點。assignee = currentUser() 或 issuetype = Bug不能把 base filter 排除的工作重新拉回；切換不會刪資料。

Sub-filter 是 company-managed Kanban 的配置，不是 Scrum 的一般設定。它與 Reports 的資料呈現也有關，但不能把「畫面只剩幾筆卡片」當成所有報表都只分析這幾筆；請依各報表定義核對，見 620.5.3。

把口語需求拆成可測的 JQL

先在進階搜尋確認每一條件，再存成 filter。以下仍使用考綱熟悉的 project、issuetype 欄位；目前介面可能顯示 space／work type。

project = BDLAB AND (issuetype = Bug OR labels = urgent)
ORDER BY Rank ASC

括號很重要：意思是「BDLAB 裡的 Bug 或 urgent 工作」。若寫成 project = BDLAB AND issuetype = Bug OR labels = urgent，其他 project 的 urgent 工作也可能被選入。

Quick filter「我的未指派工作」語意矛盾：assignee = currentUser() 與 assignee is EMPTY 不會同時成立。如果需要「我的或未指派」，在單一 quick filter 使用 assignee = currentUser() OR assignee is EMPTY。

多個自訂 quick filters 疊加以交集理解：Only mine 加 Bugs，是「我的 Bug」。若需求是 Bug 或 Task，不要同時打開互斥的 Bug 與 Task filters；用單一 issuetype in (Bug, Task)。不要與內建 Assignee picker 選多人的聯集混淆。更多 JQL 見 620.5.1。

修改前先看相依關係

Board settings → General 可以換 Saved Filter；Edit Filter Query 則是改該 filter 的內容。這兩者不同。Board 管理權不代表一定可覆寫別人擁有的 saved filter；沒有該 filter 的編輯權限時，使用 Save as 儲存新的 filter，然後把目標板改用它。

改 base filter 會讓某些 issue 進入或離開板的範圍，也可能改變 sprint／報表解讀。發布改動前記下舊 JQL、分享對象與使用此 filter 的 board。若只是會議中暫時看一組工作，新增 quick filter 比修改所有人的基礎資料範圍更合適。

演算：base 有 A、B、C；sub 保留 B、C；quick 保留 A、C。最後？

剩 C。Quick filter 不能把已被 sub-filter 排除的 A 加回。實際還必須符合權限、column mapping 與目前視圖的條件。

Demo lab：用四筆工作驗證交集

  1. 在獨立 BDLAB 建四筆：我的 Bug、我的 Task、未指派 Bug、未指派 Task。若站台不允許未指派，改用另一位測試成員，並把後續 EMPTY filter 改成該成員。
  2. 建立只包含 BDLAB 並以 Rank ASC 排序的新 filter，建立或指定給「ACP620 Filter Lab」Kanban 板；確認四筆 status 都映射。
  3. Board settings → Quick Filters 新增「Mine」：assignee = currentUser()、「Bugs」：issuetype = Bug。只啟用 Mine，預期兩筆；再啟用 Bugs，預期一筆我的 Bug。
  4. 清除 quick filters；預期四筆恢復，資料沒有被刪除。新增「Bugs or tasks」：issuetype in (Bug, Task)，確認聯集需求在單一 filter 內表達。
  5. 在測試 project 建一個測試 version，設為 Released，僅指派給一筆測試工作。於 Kanban sub-filter 加入本課的未發版／無版本範例；預期該筆不再符合 sub-filter，其餘無版本工作保留。若沒有版本管理權限，以純 JQL 逐步比對，記為配置未驗證。
  6. 回復原 sub-filter 及測試版本關係，保留練習用 quick filters。用搜尋確認四筆都仍存在。

驗收：能分別說明 base、sub、quick 排除哪一筆；確認不以刪 issue 解決卡片太多。

五題篩選設計

以下皆為原創單選情境題，非官方考古題。先選答案，再展開解析；每題只有一個最佳答案。

1．只想臨時看自己的工作，應優先用？

  1. 改所有板共用 base filter
  2. Quick filter
  3. 改 location
  4. 刪除他人工作
查看答案與四個選項解析

答案：B

A：會改變其他使用者的範圍。

B：暫時聚焦且可取消。

C：Location 不是篩選。

D：刪除不是視圖管理。

English version

You temporarily want to see only your work. What should you use first?

  1. Edit the shared base filter
  2. A quick filter
  3. Change location
  4. Delete other people’s issues
Answer and explanations

Answer: B

A: That changes scope for other users and dependent boards.

B: It provides temporary focus and can be cleared.

C: Location is not a filter.

D: Deletion is not view management.

2．Base filter 只含 WEBLAB，quick filter 指 APILAB，結果？

  1. 自動合併兩 project
  2. 全部 APILAB
  3. 空集合
  4. 把 APILAB 移入 WEBLAB
查看答案與四個選項解析

答案：C

A：Quick filter 是再篩選。

B：不能擴充 base。

C：兩個互斥條件無交集。

D：Filter 不搬工作。

English version

The base filter includes only WEBLAB; a quick filter selects APILAB. What is the result?

  1. Both projects are merged
  2. All APILAB issues
  3. An empty intersection
  4. APILAB issues are moved to WEBLAB
Answer and explanations

Answer: C

A: Quick filters narrow the scope.

B: They cannot extend the base filter.

C: The mutually exclusive conditions have no intersection.

D: Filters do not move issues.

3．要 Bug 或 Task，最適合哪個 quick filter？

  1. issuetype in (Bug, Task)
  2. Bug filter 與 Task filter 同時啟用
  3. assignee = currentUser()
  4. ORDER BY priority
查看答案與四個選項解析

答案：A

A：明確表達兩種類型的聯集。

B：互斥自訂 quick filters 疊加會沒有結果。

C：選負責人，不是類型。

D：排序不表達類型條件。

English version

Which quick filter expresses Bug or Task?

  1. issuetype in (Bug, Task)
  2. Enable separate Bug and Task quick filters together
  3. assignee = currentUser()
  4. ORDER BY priority
Answer and explanations

Answer: A

A: IN expresses the union of the two types.

B: Stacked mutually exclusive custom quick filters can return no results.

C: This selects an assignee, not types.

D: Sorting does not specify issue-type membership.

4．Kanban 排除已發版工作、仍保留無版本工作，哪個符合？

  1. fixVersion is not EMPTY
  2. resolution = Unresolved
  3. assignee is EMPTY
  4. fixVersion in unreleasedVersions() OR fixVersion is EMPTY
查看答案與四個選項解析

答案：D

A：只挑有版本，沒有判斷發版。

B：Resolution 與發版是不同資料。

C：未指派與版本無關。

D：兩個分支正好涵蓋未發版及未填版本。

English version

Which condition keeps unreleased work and work without a fix version?

  1. fixVersion is not EMPTY
  2. resolution = Unresolved
  3. assignee is EMPTY
  4. fixVersion in unreleasedVersions() OR fixVersion is EMPTY
Answer and explanations

Answer: D

A: This merely requires a version, without checking release state.

B: Resolution and release state are different data.

C: Assignment does not determine version state.

D: The two branches cover unreleased versions and missing versions.

5．Board admin 無法覆寫他人 saved filter，最適合？

  1. 一直重新整理
  2. Save as 並指定板使用新 filter
  3. 變更所有 issue types
  4. 改 working days
查看答案與四個選項解析

答案：B

A：重新整理不授予編輯權。

B：保留原 filter 並完成目標板的範圍變更。

C：類型變更與 filter 編輯權不同。

D：工作日不處理 filter 權限。

English version

A board admin cannot overwrite someone else’s saved filter. What is appropriate?

  1. Refresh repeatedly
  2. Save as a new filter and select it for the board
  3. Change every issue type
  4. Change working days
Answer and explanations

Answer: B

A: Refreshing does not grant edit access.

B: This preserves the original while changing the target board’s scope.

C: Issue types do not determine filter editing rights.

D: Working days do not address filter ownership.
