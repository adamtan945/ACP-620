設定 Scrum 估算與工時追蹤

估算用來承諾與預測；剩餘量與已記錄工時用來觀察執行。兩者可以使用不同單位。

考綱目標：Determine the effects of estimation and time tracking on Scrum boards

別把 5 points 當作 5 hours

團隊在 sprint planning 給「線上付款」5 story points，開工後以 remaining estimate 追蹤還需要多少時間。這不是互相矛盾：points 表達團隊相對規模，hours 表達時間。完成本課後，你應能區分 estimation method 與 time tracking，並解釋改設定如何影響報表。

兩個設定，要分開決定

設定／資料回答的問題使用方式
Estimation method／statistic一筆工作多大？如何累積承諾與完成？公司管理 Scrum 在 Board settings → Estimation 選方法，例如 Story points 或時間估算。依站台提供的選項，也可能使用 issue count／數值欄位。
Time tracking = None進行中用什麼追蹤？採用選定的估算方法追蹤；None 不是刪除 worklog，也不是關閉全站記錄工時。
Remaining estimate and time spent還剩多久？已花多久？可用時間追蹤進度，同時保留 points 作為 planning 的估算尺度。
Original estimate最初估多少時間？基準時間，與現在 remaining 不必相同。
Time spent／worklog已投入多少時間？由記錄工時形成；投入時間不等於工作完成。
Remaining estimate依目前資訊，還需要多少時間？記錄工時時可依介面選擇調整或保留，發現新工作也可重新估算。

Team-managed 使用 Project／Space settings → Features → Estimation 啟用，選 Story points 或 Time。不要把 team-managed 的 Story point estimate 欄位和 company-managed 的 Story Points 當成天然同一欄位；跨板前要驗證，見 620.2.2。

Company-managed 的 estimation statistic 是每張 board 的設定；即使兩張 board 指向同一 project，也不必選相同尺度。Velocity 的單位跟估算設定有關，不限 Story Points。若某個 issue type 無法填估算，先查欄位 context 與顯示設定，不能把預設適用類型誤認成產品永久限制。

設定會改變報表的解讀方式

同一 sprint 有三筆 3、5、8 points 工作，初始承諾為 16 points。若前兩筆完成，交付量為 8 points；不是「完成 2/3 所以完成 10.67 points」。以 issue count 觀察時則是三筆承諾、兩筆完成，分母已經不同。

Points 通常在工作依板的完成定義結束時才反映完成，並不是每寫一行程式就自動減少。改用 remaining time 追蹤後，burndown 可能隨剩餘時間變化；它仍需搭配範圍異動與完成欄映射解讀。

中途把估算單位由 points 改為 hours，不能把舊值視為自動換算；報表在新設定下可能顯示不同尺度與數值。先記錄原設定，對照報表說明與欄位實際值，再討論趨勢。Velocity 不是跨團隊排名，points 的尺度由團隊建立。完整報表見 620.5.3。

原估 10h，已花 4h，目前估還要 8h，代表什麼？

最新總投入預測是 12h，比原估多 2h；不是 remaining 一定要等於 10 − 4。資料反映了新的發現。應討論工作量與風險，不要為了曲線好看強迫填成 6h。

Subtask 有新增工作，不代表每條曲線都會增加

情境Burndown／Velocity 解讀
在 subtask 填 Story PointsBurndown 不計 subtask points；Velocity 也不計 subtask estimates。不要再把它們加到 parent points 造成重複計數。
Active sprint 中新增 subtask，已啟用 Remaining estimate and time spent官方視為 scope change，Burndown 會呈現該 subtask 的範圍變更；其時間估算依 tracking 行為彙總。
Active sprint 中新增 subtask，未啟用該 time tracking仍是 scope change，但 Burndown 不顯示該 subtask 的 scope change；不能因線沒動就說沒有新增範圍。
在 Burndown 的 estimation statistic 下拉選不同單位這是該報表為你保留的查看選擇，不能當成已修改共用 Board settings → Estimation 的證據。
短練習：Parent 5 points，兩個 subtasks 各 2 points，Velocity 應直接算 9 嗎？

不應；subtask estimates 不列入 Velocity。先看 parent 的完成與 board 範圍。若問題問新增 subtask 對時間 burndown 的影響，則另查 Remaining estimate and time spent，不能拿 points 排除規則回答所有時間追蹤問題。

看不到估算欄或曲線不如預期

先確認板型與管理方式，Kanban 不會提供同一套 company-managed Scrum estimation 設定。再確認選定欄位是否適用於 project／issue type、是否被 field configuration 隱藏、是否有 screen／layout 與編輯權限。最後查 issue 的實際數值、sprint 範圍與最右完成欄。把欄位加到卡片只會顯示資料，不會替空值補上估算。

記錄工時還涉及全站 time tracking、Work on Issues 等權限；Board admin 不能只靠板設定授權 worklog。相關權限與欄位見 620.3.7。

Subtask 估算：有欄位、可填值、報表計入是三件事

Company-managed 可透過 Story Points 欄位 context 擴充適用類型；但欄位可填，不表示 subtask points 會被 Burndown 或 Velocity 加總。Subtask 也可以出現在 Active sprints，不能因 backlog 的呈現方式就斷言 board 永不顯示。

Team-managed 另用 Story point estimate。官方 Estimation 說明明確列出 standard-level 與可加入 Epic，但未在該文中明確承諾 subtask 的支援範圍；不能只從「啟用後加入工作」就推論所有層級皆可用。遇到這類差異，應查該站台的 subtask 欄位設定與實際報表，不將欄位存在和統計行為合併判斷。參考 官方 team-managed estimation 說明。

Demo lab：同時保留 planning 與 execution 資料

  1. 使用獨立「ACP620 Scrum Lab」，記下原 estimation／tracking 設定。建立兩筆 Story，若使用 Story Points，填入 3、5。
  2. 另建立專用測試 sprint，加入兩筆後開始。預期 planning 總量 8 points；若無 Manage Sprints 權限，停在 planned sprint 並記錄未完成項目。
  3. 將其中一筆沿合法 transition 移到最右完成欄，查 Sprint Report／Burndown 的單位與完成量；若無其他範圍變更，預期可辨認該筆的 3 points 已完成。
  4. 只在測試板把 Time tracking 改成 Remaining estimate and time spent。為另一筆填 Original estimate 10h，記錄測試工時 4h，依目前估算填 Remaining 8h。確認這是演練資料，不是正式出勤紀錄。
  5. 開 issue 查看 points 仍為 5、time spent 為 4h、remaining 為 8h；比較報表單位，記下 tracking 與 estimation 各自影響。
  6. 回復板設定。依測試資料清理規範處理專用 worklog／sprint；不要在正式 sprint 重複練習。

驗收：你能指出 points 沒被 hours 換算，並解釋最新剩餘預測與原始估算不同的合理原因。

五題估算與追蹤

以下皆為原創單選情境題，非官方考古題。先選答案，再展開解析；每題只有一個最佳答案。

1．Story points 5 是否等於 5h？

  1. 一定等於
  2. 兩者不同尺度，不能直接換算
  3. 只在 Kanban 等於
  4. 取決於卡片顏色
查看答案與四個選項解析

答案：B

A：Points 不是時間單位。

B：估算尺度與時間資料需分開解讀。

C：板型不建立換算率。

D：顏色沒有單位含義。

English version

Does five story points mean five hours?

  1. Always
  2. They are different measures and cannot be directly converted
  3. Only in Kanban
  4. It depends on card color
Answer and explanations

Answer: B

A: Points are not a time unit.

B: Relative size and time data must be interpreted separately.

C: A board type does not establish a conversion rate.

D: Color has no unit-conversion meaning.

2．Time tracking 選 None 的意義？

  1. 刪除所有 worklogs
  2. 禁止全站記錄工時
  3. 沿用 estimation method 追蹤
  4. 取消 sprint
查看答案與四個選項解析

答案：C

A：既有 worklogs 不會因此刪除。

B：不是全站 time tracking 設定。

C：None 指不另選獨立 tracking 方法。

D：Sprint 不會被取消。

English version

What does Time tracking = None mean here?

  1. Delete all worklogs
  2. Disable time logging globally
  3. Track using the estimation method
  4. Cancel the sprint
Answer and explanations

Answer: C

A: It does not delete existing worklogs.

B: It is not the global time-tracking setting.

C: None means no separate tracking method is selected.

D: It does not cancel a sprint.

3．原估 10h、spent 4h、remaining 8h，最新總投入預測？

  1. 12h
  2. 6h
  3. 10h，永不改變
  4. 4h
查看答案與四個選項解析

答案：A

A：4 + 8 = 12，是目前預測。

B：6 是原估減 spent，不是目前 remaining。

C：原始估算不是永遠有效的上限。

D：只代表已花時間。

English version

Original estimate is 10h, time spent is 4h, and remaining estimate is 8h. What is the current total forecast?

  1. 12h
  2. 6h
  3. 10h forever
  4. 4h
Answer and explanations

Answer: A

A: Spent plus remaining is 4 + 8 = 12h.

B: Six is original minus spent, not the current remaining forecast.

C: The original estimate is not a permanent upper limit.

D: Four hours describes only effort already spent.

4．改 Scrum estimation 由 points 為時間後，應如何看趨勢？

  1. 當作完全可比較
  2. 所有 points 自動乘 8
  3. 刪除舊 sprint
  4. 重新確認欄位、單位與報表尺度
查看答案與四個選項解析

答案：D

A：尺度可能不同。

B：不存在通用 8h 轉換率。

C：刪除 sprint 不是比較方法。

D：先確定兩期量測的意義相同。

English version

After changing estimation from points to time, how should you compare trends?

  1. Assume complete comparability
  2. Multiply all points by eight
  3. Delete old sprints
  4. Check fields, units, and report scales again
Answer and explanations

Answer: D

A: The measures may differ.

B: There is no universal eight-hour conversion.

C: Deleting history is not a comparison method.

D: First establish that the periods measure comparable things.

5．設定了 points，但 issue 沒有欄位，先查？

  1. Board 名稱
  2. 欄位 context、type、screen／layout、權限
  3. 提高 WIP limit
  4. 分享 dashboard
查看答案與四個選項解析

答案：B

A：名稱不讓欄位適用。

B：顯示與可編輯性有自己的配置鏈。

C：WIP 只管欄位工作量提醒。

D：Dashboard 分享不會補上 issue 欄位。

English version

Points are configured but an issue does not show the field. What should you check?

  1. Board name
  2. Field context, issue type, screen or layout, and permissions
  3. Increase WIP limits
  4. Share a dashboard
Answer and explanations

Answer: B

A: A name does not make a field applicable.

B: Visibility and editability depend on their configuration chain.

C: WIP limits only warn about column workload.

D: Dashboard sharing does not add a field to an issue.
