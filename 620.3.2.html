考綱目標：Assign team members to project roles

同一套規則，讓不同團隊自己選人

訂餐網站與內部採購系統共用 permission scheme。兩邊都要有「可管理 sprint 的小組長」，但小組長是不同人。若 scheme 直接寫 Amy，Amy 可能在兩個 project 都獲權；改為授予 Sprint Leads role，兩個 project admin 就能各自選成員。這是 company-managed project role 的核心價值。

Role 定義、角色成員與 permission scheme

物件誰通常管理改動範圍
Role 定義Jira admin全站可用的角色名稱與描述
某 project 的 role membershipProject admin該 project 的角色人員／群組
Permission schemeJira admin所有使用該 scheme 的 projects
Group membership組織／使用者管理者可能影響多個產品與 projects

同一個人在 A 是 Developers，在 B 可以是 Observers。Group 則是全站使用者集合，例如 engineering。把 engineering 群組加入某個 project 的 Developers，是將「誰屬於群組」與「該群組在此 project 做什麼」接起來。角色成員可有個人與群組；人同時從群組與直接加入取得角色時，刪除直接加入紀錄不會移除群組路徑。

加入成員與委派設定

  1. 進入目標 project → Project settings／Space settings → People／Access。先核對頁首 project，避免在同名團隊的另一 project 操作。
  2. 選 Add people，搜尋已存在的使用者或群組，選要授予的 project role，再加入。若目前介面使用角色列表，進入角色後編輯成員，概念相同。
  3. 返回 Permissions，確認該角色被授予需要的權限。新增到未被 scheme 使用的自訂角色，不會憑空取得 Edit 或 Browse。
  4. 用一般帳號驗證一個允許與一個不允許的動作。新增成員不一定同時提供 Jira 產品授權；若無法登入，先處理帳號存取。

Administer Projects 允許維護這個 project 的角色成員。建立全新的全站角色則到 Jira settings → System → Project roles，由 Jira admin 操作。不要為了讓 project admin 加一個現有成員，就要求他具備全站管理權。

角色還可被 notification schemes、issue security levels、workflow conditions、filter／dashboard 分享使用。因此把人從「審核者」移除，影響可能包含不再收到通知、無法通過轉移條件或看不到受限 issue，不只影響編輯按鈕。

Default members 與日後維護

Jira admin 在角色的 Manage Default Members 設定預設個人／群組，會在新建立的 projects套用；這不是把現有所有 project 的成員名單回填一次。若需求是修正十個既有 projects，必須檢查各自 membership。

先預測：把 Chris 設為 Developers 的 default member，舊 project A 會自動出現 Chris 嗎？

不會。Default members 是新 project 的初始成員設定。若 Chris 因另一既存群組已有存取，這是另一條授權路徑，不能誤認為 default member 回填。

離職或轉組時，把「全站帳號狀態」「群組成員」「各 project 的直接角色成員」分開盤點。若只需要把 A 的小組長換人，優先改 A 的角色成員；若改 scheme 中的權限對象，其他共用 projects 都可能受到影響。

常見問題的檢查順序

症狀優先檢查合理處理
人加進角色卻不能看 projectRole 是否真的有 Browse；產品／站台存取；issue security補正缺少的授權，不直接給所有人 admin
People 搜不到人帳號是否存在、搜尋權限、已選對 site由帳號管理者確認；Browse users and groups 是全域搜尋能力
移除成員仍能編輯其他 role、group、直接 permission grant找出完整授權路徑
不同 project 權限一起變了是否改共用 scheme 而非 membership由 Jira admin 檢查 scheme 使用範圍
自訂角色名稱像 Admin，卻不能設定Administer Projects 是否授予該 role以 permission 定義能力，不以名稱猜測

Team-managed project 的角色與 Access 設定另有本地模型，不把這裡的共用 permission scheme 操作直接套過去；請對照 620.1.2。

Demo lab：共用 scheme，不共用同一個人

  1. 準備兩個測試 company-managed projects（ROLEA、ROLEB）與兩個一般帳號。由 Jira admin 準備測試用共用 scheme；確認沒有正式 project 使用。
  2. 使用既有角色或由 Jira admin 建立 Lab Leads，將 Browse Projects、Manage Sprints 等本次測試所需權限授予角色。
  3. A 的 project admin 只把 Amy 加入 Lab Leads；B 的 project admin 只把 Ben 加入。其他必要存取用明確、固定的測試角色提供。
  4. 以 Amy 在 A 的單一 project Scrum board 檢查 Create sprint，接著在 B 檢查相同操作。預期 A 可管理，B 不能；如果兩邊都能，查其他授權。
  5. 在 A 將 Lab Leads 從 Amy 換成 Ben，保留 scheme 不動。預期只改 A 的角色權限結果，B 不因這個 membership 操作改變。
  6. 保留檢查記錄，移除新增的測試成員與測試用角色／scheme；刪除 role 前先查 usage，別刪掉被其他 project 使用的角色。

情境練習

題目 1．同一 scheme 的兩個 project 要由不同人管理 sprint，最佳設定？

  1. Scheme 直接授予 Amy
  2. Scheme 授予 role，各 project 加不同成員
  3. 把所有人加入 jira-administrators
  4. 改 project 名稱
查看答案與逐項解析

答案 B。A 會把個人授權套到所有使用該 scheme 的 projects；B 分離能力與成員；C 過度授權；D 無關。

English version

Two projects share a scheme but need different sprint managers. What is best?

  1. Grant Amy directly in the scheme
  2. Grant a role and select members per project
  3. Make everyone a Jira admin
  4. Rename the projects

B. A applies the personal grant wherever the scheme is used. B separates capability from membership. C is excessive. D is irrelevant.

題目 2．誰能建立全站 project role？

  1. 任何 reporter
  2. Jira admin
  3. 只要有 Assignable User
  4. 任何 watcher
查看答案與逐項解析

答案 B。A、C、D 是工作相關身分或權限，沒有全站角色定義管理能力。Project admin 可維護本 project 成員，但不因而能建立全站 role。

English version

Who can create a site-wide project role?

  1. Any reporter
  2. A Jira admin
  3. Anyone with Assignable User
  4. Any watcher

B. A, C and D describe issue-related identities or permissions, not role-definition administration. Project admins can manage membership in their projects without creating global role definitions.

題目 3．改 default members 後，舊 project 沒有新成員，原因？

  1. 一定是快取
  2. 設定只作用於新 projects
  3. 必須重建所有 issue
  4. 角色不能包含個人
查看答案與逐項解析

答案 B。A 沒有必要先猜快取；B 是預設成員的範圍；C 無關且不當；D 個人與群組都可作角色成員。

English version

Why does changing default role members not add a person to an existing project?

  1. It must be caching
  2. Defaults apply to new projects
  3. All issues must be recreated
  4. Roles cannot contain individual users

B. A is an unsupported first assumption. B explains the scope. C is unnecessary and unrelated. D is false: roles can contain users and groups.

題目 4．把一個人從 role 移除，還可能影響什麼？

  1. 只有畫面顏色
  2. 通知、issue security 或 workflow condition
  3. 一定刪除他的 issue
  4. 一定取消全站產品存取
查看答案與逐項解析

答案 B。A 太狹窄；B 角色可被這些設定引用；C 不會刪資料；D project membership 與全站帳號存取不同。

English version

Removing a role member may also affect what?

  1. Only colors
  2. Notifications, issue security or workflow conditions
  3. Automatically delete their issues
  4. Always remove product access

B. A is too narrow. B lists other places roles can be used. C does not happen. D confuses project membership with account access.

題目 5．移除直接 membership 後仍在 role，可能原因？

  1. 仍經由群組取得
  2. 因為曾經是 reporter 就永久是成員
  3. 需要刪 project 才能移除
  4. 只有重設密碼才有效
查看答案與逐項解析

答案 A。群組是一條獨立來源；B 無此規則；C、D 都不是角色授權的處理方式。

English version

Why might a person retain a role after a direct membership is removed?

  1. Membership through a group
  2. Reporters keep roles forever
  3. The project must be deleted
  4. Their password must be reset

A. Group membership is a separate path. B is not a rule. C and D do not address role grants.
