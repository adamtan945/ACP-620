選 components、labels 或 custom fields

考綱目標：Recommend a method to sub-categorize issues (components, labels, custom fields)

從「想分類」追問真正需求

團隊說要把 issue 分成付款、餐點與通知。先問這些分類是否屬於本 project 的穩定子系統、是否各有負責人，以及報表是否需要跨 project 統一選項。若沒有問清楚就建立 Labels，日後可能同時出現 payment、payments、付款，報表要不斷補條件。

三種分類工具的比較

面向Jira componentsLabelsCustom fields
適用Company-managed project 內分類輕量臨時標記，可跨 project 搜尋同標籤可控的業務資料欄位
管理者Project admin 維護 component 清單有適當編輯權的人可新增標籤值Company-managed 由 Jira admin 建立與管理 context
內容Name、description、lead、default assignee自由輸入文字，常可多值依型別決定：單選、多選、日期、數字、人員等
責任可連到預設指派規則本身不會自動決定 assignee可用 automation 根據值派工
一致性同 project 使用受管理清單易有拼字與同義詞分裂預先定義選項最適合穩定報表
範圍同名 component 在不同 project 仍是不同物件同字串可在多個 project 使用透過 context 控制適用 projects／issue types

Project category 分類的是整個 project，不是個別 issue；issue type 表示工作種類，通常也牽動 workflow／screen，不宜為每個小標籤新增 issue type。先對照 620.1.3。

Components：穩定的子系統與責任

例如 Payments、Menu、Notifications 三個 components。Payments 的 lead 是 Amy，代表她負責這一塊；是否把新工作自動派給 Amy，還要看 Default assignee 設定。Lead 與 default assignee 是不同欄位。

  1. Company-managed project → Components，若導覽沒有可從 Add to navigation 加入，或到 Project settings 找 Components。
  2. 確認使用 Jira components，建立名稱、用途描述；依需要設 component lead 與 default assignee。
  3. 在 issue 的 Components 欄位選一個或多個 component。使用 JQL 例如 project = ACLAB AND component = Payments 驗證分類。
  4. 編輯或刪除 component 前看使用情況；刪除時可把相關工作改連另一 component，或移除連結，並不應以刪 issue 代替。

現行 Jira 也能使用 Compass components，代表跨系統的軟體架構目錄。那不是考綱中的 project-scoped Jira components；做自動指派 lab 前先辨識使用哪一種。Team-managed 沒有這套 Jira components 功能。

Custom field 型別怎麼選

需求型別建議原因／陷阱
只選一個支援等級Select list (single choice)／Radio buttons固定單一值；Labels 不能防止任意拼字
同時選多個受影響平台Multi-select／Checkboxes允許多個受控選項
國家再選城市Cascading select第二層選項依第一層分組，不是無限階層
預約日期／確切時刻Date picker／Date time picker日期不等於含時區的時刻
預估成本／影響人數Number數值適合排序與計算；不要為數字使用自由文字
審核者／相關團隊User picker／Group picker儲存使用者或群組身分；單選多選依需求
原因與重現步驟Paragraph支援較完整描述；Short text 適合短值
關聯版本Version picker選版本物件，不是自己打一段版本文字
外部連結依目前可用欄位型別選 URL 或合適文字欄位先確認站台欄位 catalog；不要把顯示格式當權限保護

現行欄位清單還有 Team、Assets、Formula 及應用程式提供的型別。這些補充不必全當成 2023 考綱核心。建立欄位後不能直接改型別；選錯時通常需要新欄位與資料遷移。先試小批資料、確認搜尋與報表需求再建立。

Context 決定欄位在哪些 projects／issue types 使用，以及可用選項；screen 決定操作畫面供應哪些欄位；field configuration 可控制必填或隱藏；layout 只整理呈現。欄位存在不等於每個 project 都能使用，詳見 620.3.6。

需求判讀與資料清理

情境：每週活動臨時加一個 campaign 標籤，沒有固定清單，選什麼？

Labels 很適合低成本標記，例如 campaign-autumn。先約定命名；若日後變成必填且只能選固定活動代碼，就評估受控 custom field。

情境：付款模組要有負責人，但同一 issue 可同時涉及通知模組，選什麼？

用兩個 Jira components；一筆工作可有多個 components，但 assignee 仍只有一人。多 component 的指派優先序見 620.3.5，不能以為會派給兩個 lead。

清理 Labels 前先查各值的實際使用與 board filters／automation。若用批次把 payments 統一為 payment，必須保留每張工作其他既有 labels，避免用「整欄覆寫」意外刪掉無關標記。分類變更會改變 JQL 結果與報表分組。

Demo lab：三種分類實際比較

  1. 在測試 company-managed project 建立 Payments component，填 description；保留 Default assignee 為既有設定，這一節先只測分類。
  2. 建立兩張 Task：第一張加 Payments、label campaign-autumn；第二張也加 campaign-autumn。用 component 條件搜尋預期只有第一張；用 label 搜尋預期兩張。
  3. 由 Jira admin 在隔離 context 建立 Lab support tier 單選欄位，選項 Basic／Priority，只供測試 project 使用，加入測試 screen。
  4. 在第一張工作選 Priority。嘗試輸入拼錯的 Priorty：單選不應把任意拼字新增為正式選項；Labels 則可容許新值。
  5. 做一份欄位決策表：需求、型別、是否多值、誰維護、哪些 project 使用。用此表解釋為何某需求不用 Components。
  6. 清理測試欄位前確認 context 與 usage；移除測試 labels、component 與測試 issue 的關聯，避免修改共用正式欄位。

題目 1．需要本 project 的模組分類與自動派工入口，優先選？

  1. Components
  2. Project category
  3. 只改 Summary
  4. Dashboard title

答案 A。A 有 lead 與 default assignee；B 分類 project；C 不是結構化分類；D 只是看板標題。

English version

Which feature best supports project modules with a default assignment mechanism?

  1. Components
  2. Project category
  3. Summary text only
  4. Dashboard title

A. Components support leads and default assignees. B classifies projects. C is not structured classification. D is merely a display title.

題目 2．全公司只能選 Gold 或 Silver，最合適？

  1. 自由 Labels
  2. 受控單選 custom field
  3. 每個值建立新 project
  4. 把顏色寫 Description
查看答案與逐項解析

答案 B。A 不限制拼字；B 符合固定單選與跨 project 治理；C 過度設計；D 不易一致搜尋。

English version

Everyone must select exactly Gold or Silver. What is most suitable?

  1. Free-form labels
  2. A controlled single-select custom field
  3. One project for each value
  4. Color text in Description

B. A permits inconsistent values. B supports controlled selection and cross-project governance. C is unnecessary fragmentation. D is difficult to report consistently.

  1. 直接複製 CMP screen 就可用

  3. 任何 project 都有相同 components
  4. 必須先開 sprint

答案 B。A screen 不會改 project 能力；C 忽略類型限制；D sprint 與 components 無關。

English version

How should a team-managed project handle a request for Jira components?

  1. Copy a company-managed screen
  2. Use alternatives such as labels or fields; Jira components are company-managed only
  3. All projects share components
  4. Enable a sprint first

B. A does not add project capabilities. C ignores the project-type restriction. D is unrelated.

題目 4．Custom field 建錯型別後怎麼辦？

  1. 直接改型別且資料一定無損
  2. 規劃新欄位與資料遷移
  3. 改欄位顏色
  4. 只改 board 名稱
查看答案與逐項解析

答案 B。A 型別不能直接更換；B 是合理做法且要驗證資料；C、D 不改資料型別。

English version

A custom field was created with the wrong type. What should you do?

  1. Change its type directly with guaranteed lossless conversion
  2. Plan a new field and data migration
  3. Change its color
  4. Rename the board

B. A assumes an unsupported type change. B is appropriate and needs data validation. C and D do not change the type.

題目 5．同一 issue 有兩個 components，代表什麼？

  1. 一定有兩位 assignees
  2. 一個 assignee，分類可多個
  3. 一定是兩張 issue
  4. 兩個 components 必須同一 lead
查看答案與逐項解析

答案 B。A 混淆多值分類與單一責任人；C 不會自動拆票；D 不要求相同 lead。

English version

What does assigning two components to one issue imply?

  1. Two assignees
  2. Multiple classifications but one assignee
  3. Two issues are created
  4. Both components must share a lead

B. A confuses classification and ownership. C does not happen. D is not required.
