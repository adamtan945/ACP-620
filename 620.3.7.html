把 issue 變成完整的協作紀錄

以一張付款 Bug 整合證據

一筆可接手的 Bug 至少交代現象、重現步驟與預期結果。螢幕截圖補現象；Confluence 補規格；issue link 補前後依賴；worklog 補已花工時；Bitbucket 補修正程式。這些資料互相補充，但互相不取代。

Time tracking：估算、實際、剩餘分開

Original estimate 是最初預估；Time spent 是累計 worklogs；Remaining estimate 是現在預估還需多久。已花 3 小時不代表原本 8 小時就必須剩 5；若遇到意外，你可以依 Log work 提供的選項保留或重估剩餘時間。

步驟／欄位操作與意義
顯示欄位Company-managed 將 Time Tracking 放到相關 Create／Edit screens，確保 field configuration 未隱藏；再調整 layout
授權Work On Issues 允許登錄；Edit/Delete own/all worklogs 分別控制維護範圍
Log work⋯ → Log work，填 Time spent、Date started 與工作說明，檢查 remaining estimate 選項後儲存
單位明確寫 2h、30m；不寫單位會用全站 default unit
全站設定Working hours per day／days per week 影響時間換算；不等於 board working days 日曆
資料保留隱藏或不使用 time tracking 不表示已登錄紀錄被刪除

版本差異：較舊 issue details 文章仍描述全站啟用／停用。2026-09-07 的 Configure time tracking 明確說 Jira Cloud projects 一直啟用，改用 field configuration 或 team-managed work type 欄位控制使用。因此實作先查欄位與權限，不要求找一個不存在於目前介面的總開關。Story points 與工時追蹤的 board 設定關係見 620.2.5。

已有 Work on Issues 卻不能新增工時，還要查目前 workflow status 的 properties。例如現行 Cloud 文件列出 jira.permission.work.denied（值留空），可禁止該狀態登錄工時。這是 permission scheme 以外的限制；Edit own／all worklogs 控制既有紀錄的修改，不是新增 worklog 的必要替代權限，也不要把 Edit Issues 當成一切操作的總開關。

Issue links、web links 與 Confluence

「A blocks B」從 A 看是 blocks，從 B 看就是 is blocked by。同一條有方向的關係，有 outward 與 inward 描述。Relates to 是相關，不會像 parent／child 那樣改變 hierarchy。建立 Blocks link 也不會自動讓 B 的 transition 失效；若要強制先完成 A，需額外 workflow／automation 設計。

  1. 由 Jira admin 確認 issue linking 啟用；使用者需 Link Issues 與必要可見性。跨 project 時檢查兩邊的 Browse／Link 權限與 issue security。
  2. 打開 A → Add → Linked issue，選 blocks，再選 B；回 B 檢查反向描述是否正確。
  3. 如果只是外部測試報告，使用 Web link，輸入 URL 與清楚的 link text；不必為每個文件建立假 issue。
  4. Confluence 連結可貼到描述或從新增相關內容入口加入。用一般帳號驗證文件權限；Jira 可見不等於 Confluence 可見。

Jira admin 能管理 link type 的 Name、Outward description、Inward description；刪除 link type 可影響既有 links，變更名稱也可能影響 JQL。不要為了單張工作隨便改全站 Blocks。某些已關閉 issue 不出現在建議清單，可用精確 issue key 查找。

附件、留言、@mention 與 watchers

附件可以直接拖進 issue 或描述／留言。若上傳失敗，先查 Create Attachments、檔名、單檔大小與總儲存空間；不能只因 Edit Issues 正常就認為附件權限正常。Delete own attachments 與 Delete all attachments 分開：能上傳並不保證能刪除別人的檔案。

描述適合維護目前共識，留言適合保留討論與事件。@mention 使用者後會嘗試通知對方，但對方仍需存取該 issue；Browse users and groups 會影響人員搜尋範圍。把人設 watcher 是訂閱更新，不是指派責任。個人設定可控制自己更新／留言後是否自動 watch。

Watch 圖示或 W 可切換自己追蹤；View Voters and Watchers 管名單可見性，Manage Watchers 管加入／移除他人。現行操作指南對名單 UI 同時列兩項，權限細分頁則分開描述；若「看名單」入口受限，檢查兩項與使用中的介面。分享 issue URL 不會改它的 permission scheme 或 security level。

演練：同事被 @mention 卻打不開 issue，應先把他設為 assignee 嗎？

先檢查 project Browse、issue security 與帳號存取。通知不是權限。Assignee 也不是一般性的存取解鎖方式；只有方案明確以 Current assignee 作授權時，指派才可能間接影響可見性。

自己 Watch 不等於管理別人的 watcher：缺少 Manage Watchers，不能因此推論自己不能追蹤。留言與工時也要按動作分開：Add Comments／Work On Issues 用於新增；Edit All Comments／Edit All Worklogs 可維護他人既有紀錄，不能用「All」推論同時具備 Delete 或新增權限。排錯時列出誰的紀錄、要新增／改／刪哪一種，再查對應權限。

通知寄件者與收件者分開設定：Team-managed 可在 Project／Space settings → Notifications 配置事件與收件角色，也能設定通知寄件地址；不是只有 company-managed 才能調整通知。設定通知不會替收件人增加工作存取權。見 官方 team-managed 通知說明。

Bitbucket：讓 issue key 連起程式與工作

Jira Cloud 與 Bitbucket Cloud 連接後，在 branch name、commit message 或 pull request title 放入 issue key，例如 ACLAB-12-fix-payment，Jira 就能把相關開發活動連到那張工作。只貼 repository 首頁 URL 不等於建立這種工作關聯。

Development panel 與 Releases 可呈現 branches、commits、PR、build 與 deployments，視已連接的工具而定；使用者要具備 View Development Tools。點進 Bitbucket 看程式碼還要 Bitbucket 本身的存取權。

一般包含 key 的 commit 是連結證據，不代表一定自動轉移 status。Smart Commits 可用特定語法登錄時間、留言或執行 transition，還涉及使用者身分與權限；PR 事件也可觸發 automation。遇到「PR merged 但 issue 未完成」，要查有沒有配置這些規則，不能只看 integration 已連線就當作應自動完成。參見 620.4.1。

批次編輯不是所有欄位的通用入口

即使具有 Make bulk changes 與各張工作的必要權限，標準 Bulk edit 仍不能直接改 Summary、Description 或 Resolution。前兩者不能因單張可編輯，就推論批次表單一定提供；Resolution 應透過合適的 workflow transition／Bulk transition 處理，並滿足轉移條件與欄位規則。不要為了修正 Resolution，只把 status 名稱改成 Done。

Demo lab：完整交接一張 Bug

  1. 在隔離測試 project 建立 A「付款失敗」與 B「完成驗收」，只放虛構測試資料。Description 寫重現步驟、實際結果、預期結果。
  2. 附上一張不含敏感資訊的測試圖；加入一個可供練習帳號讀取的文件 URL。以一般帳號確認附件可開、文件仍遵守其自身權限。
  3. 建立 A blocks B；從 B 驗證 is blocked by A。尝試查看 B 的可用 transition，理解連結本身沒有新建 workflow condition。
  4. 將 Time Tracking 放入隔離 screen/layout；一般帳號有 Work On Issues。為 A 填 Original estimate=2h，Log work=30m，明確選擇剩餘時間處理方式。檢查 Time spent 與 Remaining。
  5. 只使用自己的測試帳號或已同意參與的帳號練習 watch／@mention，確認通知設定；不對不相關同事發測試訊息。
  6. 若已有獲准連接的測試 Bitbucket repo，建立含 A key 的測試 branch／commit，觀察 Development panel。若沒有，做紙上 key 對照即可，不為練習授權整個正式 workspace。
  7. 還原測試設定；清理附件、links、worklogs 須具相應權限。保留每個資訊類型「放哪裡、誰可見、如何驗證」的筆記。

情境練習

題目 1．A blocks B 是否一定禁止 B 開始？

  1. 是，任何 link 都是 workflow validator
  2. 否，需額外 workflow／automation 規則
  3. 只要 B 有附件就禁止
  4. 必須相同 assignee 才會禁止
查看答案與逐項解析

答案 B。A 誤把關聯當強制流程；B 正確；C、D 無此規則。

English version

Does A blocks B necessarily prevent B from starting?

  1. Yes, every link is a validator
  2. No, additional workflow or automation rules are needed
  3. Only if B has attachments
  4. Only if both share an assignee

B. A confuses relationships with enforcement. B is correct. C and D are not rules.

題目 2．能 Edit Issues 卻不能 Log work，先查？

  1. Work On Issues 與 Time Tracking 欄位
  2. 改 component 名稱
  3. 把 issue 複製十次
  4. 只需改 Description
查看答案與逐項解析

答案 A。A 同時檢查操作權限與欄位供應；B、C、D 無法提供工時能力。

English version

A user can edit issues but cannot log work. What should you inspect?

  1. Work On Issues and the Time Tracking field
  2. The component name
  3. Clone the issue ten times
  4. Only change Description

A. A checks permission and field availability. B, C and D do not provide time logging.

題目 3．Original estimate=8h，已花3h，Remaining 能是7h嗎？

  1. 不可能
  2. 可以，剩餘是目前重新估算
  3. 只要改成 Story points 才行
  4. 代表已花10h
查看答案與逐項解析

答案 B。A 把原始估算當不可變公式；B 正確；C 不需要換估算單位；D 已花仍是3h，3+7 是目前總預測。

English version

Original estimate is 8h and spent time is 3h. Can remaining time be 7h?

  1. Impossible
  2. Yes, remaining time is the current estimate
  3. Only after switching to story points
  4. It means 10h has already been spent

B. A treats the original estimate as a fixed equation. B is correct. C is unnecessary. D confuses spent time with the revised total forecast.

題目 4．分享 Jira URL 給同事會給他 Confluence 讀取權嗎？

  1. 會，所有 Atlassian 權限相同
  2. 不會，要各自檢查存取
  3. 只有加 watcher 就會
  4. 只要連結是藍色就會
查看答案與逐項解析

答案 B。A 混淆產品授權；B 正確；C watch 是通知；D 顏色不是權限。

English version

Does sharing a Jira URL grant Confluence access?

  1. Yes, all Atlassian permissions are identical
  2. No, check each product’s access
  3. Adding a watcher grants it
  4. A blue link grants it

B. A confuses separate access models. B is correct. C is notification membership. D is styling, not permission.

題目 5．連接 Bitbucket 後如何讓 commit 關聯到 issue？

  1. 在 commit message 放 issue key
  2. 只寫 done
  3. 只把 Jira avatar 改成 repo 圖
  4. 每張 issue 都要 Jira admin 才看得到
查看答案與逐項解析

答案 A。A 是原生關聯入口之一；B 無法辨認是哪張工作；C 無關；D 檢查 View Development Tools 等權限，不要求每人 admin。

English version

After connecting Bitbucket, how can a commit be associated with an issue?

  1. Include its issue key in the commit message
  2. Write only done
  3. Change the Jira avatar
  4. Require every reader to be a Jira admin

A. A provides an association key. B does not identify the issue. C is irrelevant. D overstates the requirement; check View Development Tools and related access.
