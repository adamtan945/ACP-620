考綱目標：Identify ways to automate Jira (bulk change, workflow, automation, apps)

1．同樣是省下手動操作，執行時機不同

訂餐團隊有四個需求：把既有30張測試卡補上標籤；每週寄出待處理清單；完成工作時填入 Resolution；新建高優先級 Bug 自動交給指定人。它們不必全部做成長期 automation rule。完成本節後，你能對每個需求說出觸發時機、作用對象、權限與最合適的做法。

Automation for Jira 現行介面可能寫 Automation flows；rule 與 flow 在本課代表同一類規則，不是另一款不同工具。Apps 是擴充能力的方式，並非所有動作都需要安裝 app。

2．情境選型表

區別在於「何時執行、在哪裡定義、能影響誰」。例如不要為了一次加標籤而留下每次更新都會跑的規則；也不要用訂閱期待 Jira 自動改 assignee。

3．Bulk change：先查對集合，再選對操作

進階搜尋找到練習集合後，由 More actions → Bulk Change all <n> issues／work items，先勾選對象，再選操作、填值、檢閱並 Confirm。Make bulk changes 是 global permission；每張 issue 還要有對應 project permission。一次最多可編輯1000張，這不代表有權操作搜尋結果裡所有資料。

Bulk 操作適用目的額外檢查
Edit改Priority、Labels等支援欄位Edit Issues；某些欄位另需Schedule Issues或Modify Reporter
Transition經既有workflow轉換狀態要走可用transition並填必填欄位；不同workflow分組處理
Move搬到另一project或更換需搬移流程的typeMove及目的Create等權限、status/field mapping、版本與component差異
Delete刪選定工作不可當作一般清理演練；先確認資料與授權
Watch／Stop watching批次追蹤或取消自己的追蹤改追蹤關係，不是改工作內容

Bulk Edit 不是所有欄位都可選。官方列出 Summary、Description、Attachments、Environment、Resolution 與 time tracking 欄位等不供此操作直接批次編輯。改 project 用 Bulk Move；Resolution 應透過合適 workflow transition。選不到欄位也可能因不同project、field configuration、context或權限，先找原因。

需要通知時依畫面選擇 Send mail for this update；能否取消受權限與角色限制。涉及 Move 時更要先核對來源與目的資料模型，尤其 company-managed → team-managed 可能失去 components／versions；本課 lab 不做搬移或刪除。

批次操作先分「改欄位」與「走流程」

要做的事為何不是同一種操作
把一批工作移到另一個 status用 Bulk transition，按 workflow 分組並滿足 transition 條件／必填值
直接改 Resolution不能把它當普通 Bulk edit 欄位；用適當 workflow transition 設定或清除
更改 Summary 或 Description不能假定通用 Bulk edit 支援；先確認操作提供的欄位
把工作搬到另一個 projectBulk move 要檢查目的地 Create、type、欄位及資料對應
關注一批工作Bulk watch 是自己的關注，不等於替所有同事加入 watchers
反例：搜尋得到 80 筆，是否能一次全部改成功？

搜尋成功只證明看得到。還要有 Make bulk changes 及各工作所需的操作權限；不同 workflow、狀態與必填條件也可能拆成不同處理組。先核對數量與對象，再在確認畫面檢查實際會變更的集合。

4．Filter subscription：定期寄集合，不是監看單張變更

project = FOOD AND issuetype = Bug
AND statusCategory != Done
ORDER BY priority DESC, created ASC

把FOOD換成demo key，先跑查詢，再 Save as「ACP620 Weekly Bugs」。開 filter 的 Details → New subscription，選自己與排程；UI可提供一般頻率或Advanced cron。個人練習只訂給自己。若要訂給群組，需要 Manage Group Filter Subscriptions global permission，而且只能選自己所屬群組。

訂閱寄的是執行當時符合query的工作，不只寄「從上次以來有變更的」。如果要看最近更新，必須在JQL寫出updated條件；如果只想收到某張issue每次變動，使用Watch。訂閱最多寄前200筆，排序因此很重要，不可把郵件當作全量匯出。

currentUser() 對每位真正的訂閱收件人分別求值；group email alias／distribution list 不等於逐人訂閱。收到相同filter的兩個人可能因身分及可見權限而得到不同結果。跨課參照 JQL集合、global與project permissions。

選工具先看「一張卡」還是「一組查詢」

Watch 適合追蹤自己關心的一張工作的事件；filter subscription 適合定期收到一組查詢結果；automation 可依事件或排程執行動作。若需求只是每天寄一份固定 filter，不應先設計大量逐筆訊息。訂閱群組與分享 filter 也不同：能看 filter 不等於能管理 group subscription。

5．Workflow post functions：把規則放在轉換上

Conditions 管是否可執行轉換；Validators 在轉換前驗證輸入，失敗就不進目的status，也不執行post functions。Post functions 做轉換後的額外處理，例如設定欄位、指派、記錄變更與發出事件。不要用post function替代「必填資料才能過關」的validator。

常見例子是：進Done時設定Resolution，reopen時清空Resolution。這讓 issue analysis reports 的未解決口徑正確。新增自訂post function應使用獨立測試workflow並由具權限的admin發布draft；共用workflow的修改會影響所有使用者。現行UI可能有新版workflow rule用語，請依實際編輯器與管理方式確認支援。

Jira的必要post functions包含status、history、index及event等流程處理，不要刪改必要順序，也不要任意改動預設Generic event。追加自訂行為時遵循文件的放置位置；一般project admin不能因為管理project就推論可以更改所有共用workflow。

6．互動選型：先自己選，再展開理由

只想今天把選定20張Bug標成待複查

選Bulk edit，先限定20張並確認新增標籤不清除舊值。未來issue不需要自動重做，因此不必留下廣泛觸發規則。

每次有人把工作轉到Cancelled，都要填入取消原因的Resolution

評估該transition的post function；若使用automation，還要接受它作為後續事件處理及執行權限／失敗監控的差異。規則如果只屬於某個workflow，就先在workflow層設計。

每天找過期且未完成工作，把Priority升高

需要改資料，用Scheduled automation + JQL +必要條件。Filter subscription只通知，不會升Priority。先從一張demo卡與Log action驗證。

7．Demo lab：同一集合，比較批次修改與定期通知

只使用隔離demo project與三張新建測試卡，全部加acp620-bulk-lab標籤。記錄它們的實際keys、原Priority與Labels。沒有bulk permission時，先完成搜尋與選型練習，不調高自己的全站權限。

步驟預期結果
用project及labels精確搜尋，確認只有3張清單數量與keys符合準備資料
Bulk Edit增加review-needed標籤；若UI提供替換／新增，選新增原acp620-bulk-lab仍在，新增review-needed；其他卡不變
另建立第四張只有acp620-bulk-lab的卡第四張不會自動取得review-needed，證明bulk是一次操作
儲存查詢作為filter，進New subscription檢查頻率與自己作為收件人可設定定期通知；若不想收信，完成設定辨識後取消，不必實際訂閱
在練習紀錄寫下若改用Issue created rule會怎樣未來符合條件新卡才自動處理；既有卡不會因啟用規則而全部補跑

本課只提供操作教材，沒有代替你寄信或修改Jira。演練完成可保留卡片供下一節使用；不需要批次刪除來證明理解。

  2. Bulk Move

English version

Send a weekly list of unfinished work without changing it. Choose.

  1. Filter subscription

B。A把global能力誤當所有資料授權；B需同時滿足；C識別碼不是權限。

English version

Does Make bulk changes permit editing every issue?

  1. Yes
  2. Relevant project permissions are also required
  3. Knowing the key is sufficient

B. A confuses a global capability with access to all data. B requires both layers. C treats an identifier as permission.

  2. 一定是權限壞了

English version

A fourth issue created after a bulk label update has no new label. Why?

  2. Permissions must be broken

A. This is expected one-time behavior. B lacks evidence. C does not trigger edits.

6．訂閱郵件只有200筆，而搜尋350筆，先查？

  1. 訂閱結果上限與排序
  2. 刪掉150筆
  3. 認定JQL一定錯
查看答案與逐項解析

A。A對應目前前200筆限制；B破壞資料；C不能由郵件筆數直接推論。

English version

A subscription emails 200 items but search returns 350. Check.

  1. Subscription limit and sorting
  2. Delete 150 items
  3. Assume invalid JQL

A. A matches the current first-200-result limit. B destroys data. C is not implied by the email count.

7．公司管理共用workflow的Done轉換要自動設Resolution，合理做法？

  1. 與Jira admin在測試workflow驗證post function再發布
  2. 任意移除所有必要post functions
  3. 只把board欄位改名
查看答案與逐項解析

A。A涵蓋權限、共用影響與驗證；B會破壞必要流程；C只改呈現，不設定Resolution。

English version

A shared company-managed workflow should set Resolution on Done. Best approach?

  1. Validate a post function on a test workflow with a Jira admin, then publish
  2. Remove all essential post functions
  3. Rename the board column

A. A covers authority, shared impact and validation. B breaks required processing. C changes presentation, not Resolution.
