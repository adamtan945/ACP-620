考綱目標：Translate business requirements into appropriate JQL queries

1．先決定「要找誰」，再決定「怎麼排列」

訂餐網站團隊問：「請列出本專案尚未完成、交給我或還沒有人接手的 Bug，優先看最早到期的。」先圈出資料範圍 project、工作種類、完成定義、負責人與排序。JQL（Jira Query Language）回傳符合條件的 issues；它不會修改資料，也不是用 SELECT／JOIN／GROUP BY 算總和的 SQL。

project = FOOD AND issuetype = Bug
AND statusCategory != Done
AND (assignee = currentUser() OR assignee IS EMPTY)
ORDER BY due ASC, priority DESC

FOOD 是示範 key，需替換成自己的 demo project。statusCategory != Done 用三大狀態類別排除完成；若需求明確要求「沒有 Resolution」，則改用 resolution IS EMPTY。這兩種口徑不要在報告中混用。排序只改呈現順序，不會多找或少找 issue。

2．四個零件：field、operator、value／function、keyword

零件作用本課例子
Field取出每筆 issue 的欄位project、assignee、created、labels
Operator指定如何比較=、IN、>=、IS EMPTY、~
Value固定比對值FOOD、Bug、"2026-09-01"
Function執行查詢時計算值或集合currentUser()、startOfDay()、openSprints()
Keyword連接、否定或排序子句AND、OR、NOT、ORDER BY、ASC、DESC

一個子句是「欄位 + 運算子 + 值或函式」。函式要有括號；列表通常搭 IN，例如 sprint IN openSprints()，不是 sprint = openSprints()。引號用在含空格或特殊字元的名稱，例如 status = "In Progress"。保留字作為值也要加引號。

一般內建 JQL 無法直接寫 assignee = reporter 或 timeSpent > originalEstimate 來逐筆比較兩個欄位。先看是否有既有衍生欄位，例如 workRatio；複雜比較才評估匯出或核准的 app。不要把 app 提供的函式誤認成所有站台都有。

3．AND 縮小、OR 放大；空值要另外接住

需求「FOOD 專案的 Bug 或 Task」可寫 project = FOOD AND issuetype IN (Bug, Task)。混用 AND／OR 時，使用括號清楚圈出同一層需求，不依靠讀者猜優先順序。下列第一段會把其他專案所有 Task 也納入，第二段才符合需求。

(project = FOOD AND issuetype = Bug) OR issuetype = Task

project = FOOD AND (issuetype = Bug OR issuetype = Task)
需求可用條件容易漏掉什麼
未指派assignee IS EMPTYEMPTY 不是名叫 Unassigned 的使用者
不是我，包含未指派(assignee != currentUser() OR assignee IS EMPTY)!= 不包含空值
沒有 urgent 標籤，包含無標籤(labels NOT IN (urgent) OR labels IS EMPTY)NOT IN 也不自動包含空值
同時有 frontend、paymentlabels = frontend AND labels = paymentIN (frontend,payment) 只要求任一個
Summary 提到 checkoutsummary ~ "checkout"= 不適用 Summary 的全文搜尋

多值欄位要先問「至少一個」還是「全部都要」。不要把 labels = frontend AND labels = payment 判定成不可能：同一張卡可以有多個 labels。要排除一個標籤，也需注意其他標籤與空值的測試案例。

反例：不等於某個人，是否包含未指派？

assignee != currentUser()找的是「有負責人，而且不是我」，不會自動包含 EMPTY。若需求是所有不是我負責的工作，連尚未分派也要追蹤，需明寫(assignee != currentUser() OR assignee IS EMPTY)。相同原則也適用於很多可留空欄位的!=與NOT IN；不能把資料庫的空值想成普通的另一個選項。

原創反例：甲指派給我、乙指派給同事、丙未指派；兩種查詢各回傳誰？

只寫不等於目前使用者會回傳乙；加上 OR assignee IS EMPTY 才回傳乙與丙。若還要限定專案，外層寫project = FOOD AND (assignee != currentUser() OR assignee IS EMPTY)，避免其他專案的空值工作漏進來。

EMPTY、NULL 與空字串不要混用

labels IS EMPTY或labels IS NULL用來找沒有標籤的工作。官方 Keywords 也示範 duedate = EMPTY 與 duedate = NULL，所以不能一概說等號永遠不支援空值。先核對該欄位支援的運算子；教材以 IS EMPTY 表達最清楚。空字串 '' 不等於通用空值關鍵字。題庫若出現 IN (NULL) 等變體，不把它延伸成所有欄位皆支援的通則；需另外核對實際查詢。參考 JQL Keywords。

4．把常見業務詞對到正確欄位

業務問題欄位與示範辨識要點
版本要修哪些工作project = FOOD AND fixVersion = "1.1"affectedVersion 是問題發生在哪版，不是預計修復版
哪個 Epic 的直接子工作parent = FOOD-10新查詢使用 parent；不是自動遞迴整棵階層
誰回報／誰建立reporter = currentUser()／creator = currentUser()Reporter 可以變；Creator 表示原始建立者
目前在做status = "In Progress"特定 status 名稱與 statusCategory 的 In Progress 類別不同
目前沒有解決原因resolution IS EMPTY不能因為 status 名字叫 Done 就假設 Resolution 已正確填入
超過原估時的 100%workRatio > 100需要 time tracking 資料；這是既有比率欄位
沿用已儲存篩選器filter = 12345 AND priority = High12345 必須換成實際 filter ID；ID 比名稱穩定

版本及 components 是 project 層級資料；同名值可能存在於不同 project。加 project 範圍或使用實際 ID，避免把同名版本當成同一個 release。全文的 text ~ "checkout" 搜尋多個文字欄位，若只想查標題就用 summary，減少語意歧義。

5．日期、動態函式與歷史：現在是什麼，曾經是什麼

project = FOOD
AND created >= "2026-09-01" AND created < "2026-10-01"
ORDER BY created ASC

project = FOOD AND due < startOfDay()
AND statusCategory != Done

project = FOOD AND updated >= "-7d"

project = FOOD AND status CHANGED TO "Done" AFTER startOfMonth()

第一段包含 9 月 1 日零時，排除 10 月 1 日零時，能涵蓋整個 9 月。日期時間依使用者設定時區解讀；due 是日期欄位。第二段找「今天以前到期」；第三段是滾動七天，並不等於這個日曆週。startOfWeek() 的週起點受設定影響，團隊約定週一之前先確認，不要假設所有站台相同。

函式／運算子用途限制或陷阱
currentUser()以目前檢視者為準共享後每人可能看到不同結果
openSprints()／futureSprints()／closedSprints()已開始未結束／未開始／已完成的 sprint 集合issue 可能同時保有過去與現在 sprint，closedSprints 不等於 issue 已完成
unreleasedVersions(FOOD)未 release 的版本集合搭 fixVersion IN；版本未 release 不代表卡片未 Done
membersOf("demo-group")依實際群組成員搜尋群組名稱必須存在；不是輸入 project role 名稱
WAS "In Progress"目前或曾有該值不能拿來查每一種欄位的歷史
CHANGED FROM "Done" TO "In Progress"指定欄位變更事件Status、Assignee 等支援，labels 不支援 CHANGED

status = Done 查現在；status WAS Done 包含過去；status CHANGED TO Done 查變更紀錄。歷史搜尋支援欄位有限，要核對 reference，不能把 AND updated >= 某日當作「狀態在那天改過」。updated 也可能只是描述被編輯。

歷史事件與現在狀態：兩個條件不能互相代替

status WAS Done AND status != Done表示曾經在 Done，現在已不是 Done。status CHANGED FROM Done只要求歷史上發生過離開 Done 的轉換，不限制現在在哪裡。工作經過 Done → In Progress → Done，符合第二種，卻不符合第一種。若要找目前重開、而非所有曾離開完成狀態的工作，就需要加目前狀態條件；也要確認站台實際狀態名稱。

日期欄位：更新過，不代表在那天解決

resolved／resolutiondate是解決日期；updated是最後更新時間。工作上月解決，本週補一則留言，可能符合本週 updated，卻不符合本週 resolved。要統計解決數，先用 resolved 的區間，再確認 Resolution 設定正確；不要因題目提到「最近」就一律選 updated。

「前一個完整曆週」與「從現在往回七天」是不同集合。前者可用resolved >= startOfWeek("-1") AND resolved < startOfWeek()，後者可用resolved >= "-7d"。以站台的時區與週起始設定解讀；半開區間可避免下一週邊界重複計算。startOfDay("-7d")則從七天前午夜開始，也不完全等於此刻往回168小時。

版本函式：最新一個與全部已發布版本

函式完整名稱是latestReleasedVersion("FOOD")，不是latestReleased()。例如fixVersion = latestReleasedVersion("FOOD")找最新已發布版本；fixVersion IN releasedVersions("FOOD")找所有已發布版本的工作。一般列舉寫IN ("1.0", "2.0")，而集合函式本身已有呼叫括號，不要把所有 IN 寫法混成一種。最新版本依 Jira 的版本排序判定，不要自行把版本名稱當數值最大值。

原創反例：只有1.0已發布時，兩個函式是否永遠相同？

當時兩者可得到同一個版本集合；等2.0也發布，releasedVersions仍包含1.0與2.0，latestReleasedVersion只取最新一個。一次查到相同結果，不表示兩個函式語意相同；也不能推論所有專案的「第一個已發布版本」一定叫1.0。

earliestUnreleasedVersion("FOOD")找版本排序中的最早未發布版本；不要依名稱或日期自行推算。archivedVersions()與mergedVersions()不是此處的標準 JQL 函式；介面有 Archive／Merge 動作，不代表 JQL 必有同名函式。

下一個未發布版本的函式名稱：官方列的是 earliestUnreleasedVersion("FOOD")，未列出 nextUnreleasedVersion()。不要依口語「next release」自行拼出函式。若需求鎖定特定版本，直接用 project = FOOD AND fixVersion = "2.4" 更明確；版本排序改變後，動態函式選到的版本也可能改變。

搜尋歷史、查看紀錄與還原變更是三件事

WAS／CHANGED 用來找符合歷史條件的工作，不會執行還原。要確認某筆欄位由誰、何時改動，查看該工作 History；若由 Automation 修改，再對照 flow audit log 的執行紀錄。

Jira 管理介面的 audit log 主要追蹤設定等重要活動，例如 workflow、必填欄位與角色變更，不能當成每筆工作的完整欄位歷史。若需要復原，仍須依舊值、目前權限及 workflow 規則執行適當編輯或轉換；搜尋結果本身沒有 undo 功能。參考 Jira audit log 與 Automation 排錯文件。

6．互動推理卡：先選意圖，再展開查詢

先自行寫答案，再展開最符合需求的卡片。這些是離線教學案例，不會連線或執行 Jira 查詢。

我要找「沒有指派給我」，且包括沒人接的工作
project = FOOD
AND (assignee != currentUser() OR assignee IS EMPTY)

反例檢查：指派給自己→排除；指派給別人→納入；空白→OR 分支納入。若漏掉 OR，第三筆就不見了。

我要找「九月建立」；九月最後一天深夜也要算
project = FOOD
AND created >= "2026-09-01"
AND created < "2026-10-01"

三個邊界：9/1 00:00 納入、9/30 23:59 納入、10/1 00:00 排除。不要用 created <= "2026-09-30" 代表整天。

我要找「上一個 sprint 沒做完、現在繼續做」的候選工作
project = FOOD
AND sprint IN closedSprints()
AND sprint IN openSprints()
AND statusCategory != Done

可找同時保有已結束與進行中 sprint 的未完成工作。這只是候選集合；不是特定相鄰 sprint 的證明。若需精確上一期，改用那兩期的實際 sprint ID 並核對 Sprint Report。

8．原創情境題與逐項解析

1．希望包含「其他人負責」和「未指派」，哪個正確？

  1. assignee != currentUser()
  2. assignee != currentUser() OR assignee IS EMPTY
  3. assignee = EMPTY AND assignee = currentUser()
查看答案與逐項解析

B。A 漏掉空值；B 明確補上未指派；C 要求同時空白與等於目前使用者，無法符合需求。

English version

Include items assigned to other people and unassigned items. Which query works?

  1. assignee != currentUser()
  2. assignee != currentUser() OR assignee IS EMPTY
  3. assignee = EMPTY AND assignee = currentUser()

B. A excludes empty assignees. B explicitly includes them. C requires an assignee to be both empty and the current user.

2．找同時有 web 與 payment 兩個 labels？

  1. labels IN (web,payment)
  2. labels = web AND labels = payment
  3. summary ~ "web payment"
查看答案與逐項解析

B。A 只要任一標籤；B 對多值欄位要求兩者都有；C 查文字內容，不查 labels。

English version

Find items containing both the web and payment labels.

  1. labels IN (web,payment)
  2. labels = web AND labels = payment
  3. summary ~ "web payment"

B. A requires either label. B requires both on a multi-value field. C searches summary text, not labels.

3．哪個表示「本月曾轉成 Done」，不要求現在仍是 Done？

  1. status = Done
  2. updated >= startOfMonth()
  3. status CHANGED TO Done AFTER startOfMonth()
查看答案與逐項解析

C。A 是目前狀態；B 只知道 issue 有更新，可能改其他欄位；C 指定了狀態轉換事件與時段。

English version

Find items that transitioned to Done this month, even if no longer Done.

  1. status = Done
  2. updated >= startOfMonth()
  3. status CHANGED TO Done AFTER startOfMonth()

C. A checks current status. B includes any update, not necessarily a transition. C specifies a status change and period.

4．共享含 currentUser() 的 filter，Alex 和 Bea 結果不同。最合理？

  1. 函式依各自登入身分求值
  2. filter 一定損壞
  3. 只有 owner 可執行函式
查看答案與逐項解析

A。A 是預期的動態行為，另有可見權限差異；B 沒有證據；C 不是此函式的規則。

English version

Alex and Bea get different results from a shared filter using currentUser(). Why?

  1. The function evaluates for each viewer
  2. The filter must be broken
  3. Only its owner can use the function

A. The function is dynamic for the signed-in user; visibility can also differ. B has no supporting evidence. C is not a restriction of currentUser().

5．正確搜尋進行中 sprint 的 issues？

  1. sprint = openSprints()
  2. sprint IN openSprints()
  3. status = openSprints()
查看答案與逐項解析

B。A 把集合函式搭成單值比較；B 是支援的欄位與運算子；C 把 sprint 集合用到 Status 欄位。

English version

Which query finds items in active sprints?

  1. sprint = openSprints()
  2. sprint IN openSprints()
  3. status = openSprints()

B. A uses a single-value operator with a set-returning function. B uses the supported field and operator. C puts sprint values against Status.

6．九月建立的資料，用哪種邊界最清楚？

  1. created >= "2026-09-01" AND created < "2026-10-01"
  2. created = "2026-09-01"
  3. created <= "2026-09-30"
查看答案與逐項解析

A。A 包含整月且不跨到十月；B 只比對起點，不是整月；C 沒有起始邊界，也可能漏掉9/30午夜之後。

English version

Which boundary clearly covers all of September?

  1. created >= "2026-09-01" AND created < "2026-10-01"
  2. created = "2026-09-01"
  3. created <= "2026-09-30"

A. A includes the full month and excludes October. B only compares to one timestamp. C has no lower boundary and can omit September 30 after midnight.

8．一般內建 JQL 能直接做什麼？

  1. SELECT SUM(storyPoints) GROUP BY assignee
  2. assignee = reporter，逐筆比對兩欄
  3. project = FOOD ORDER BY created DESC
查看答案與逐項解析

C。A 是 SQL 類聚合，不是內建 JQL；B 不支援直接欄位對欄位比較；C 合法篩選並排序。

English version

What can ordinary built-in JQL do directly?

  1. SELECT SUM(storyPoints) GROUP BY assignee
  2. Compare two fields per item with assignee = reporter
  3. project = FOOD ORDER BY created DESC

C. A is SQL-style aggregation. B is unsupported field-to-field comparison. C filters and sorts items.
