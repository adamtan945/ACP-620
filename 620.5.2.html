LESSON 620.5.2 · REPORTING

選擇 gadgets，組成真正能回答問題的 dashboard

Dashboard 是共用的觀察窗口。先決定誰要做什麼決策，再配置資料來源、圖表、分享與更新頻率。

考綱沿用 project／issue／issue type／rule；現行文件可能稱 space／work item／work type／flow。依功能辨認入口；先確認管理方式、權限與方案。下列互動均為本機模擬，實作步驟只供隔離的 demo site 跟做。

考綱目標：Determine an appropriate gadget and dashboard configuration

1．先寫三個決策問題

訂餐團隊早會只需要知道：今天誰該接手未指派工作？Bug 是否集中在某個狀態？新進工作是否超過解決速度？把這三題變成 dashboard，就比放十張好看的圖更有用。完成本節後，你應能建立 dashboard、配置 gadgets，並說明「看到儀表板」為什麼不等於「看到全部資料」。

這是權限檢查的概念圖。每個 gadget 的來源可能是 project、filter、sprint 或目前使用者，不一定都經過 saved filter；共享 dashboard 不會把 owner 的資料權限傳給 viewer。

2．問題與 gadget 的對照

想知道什麼建議 gadget配置與解讀
需要逐筆處理的工作清單Filter Results指定已儲存 filter；顯示 Key、Summary、Assignee、Status、Due 等必要欄位
目前哪些工作交給我Assigned To Me依目前檢視者顯示；適合個人待辦，不適合固定某人的全團隊報表
各優先級占多少Pie Chart選 project／filter 與 Priority；表達件數分布，不能推論工時占比
各負責人的狀態分布Two Dimensional Filter Statistics同一 filter，X=Assignee、Y=Status；交叉表可找集中區
單一欄位各有幾件Issue Statistics／Work item Statistics同一 filter 依 Status 或其他可選欄位分組
新工作進來是否比解決快Created vs Resolved選期間與區間；先確認 Resolution 資料可靠
未解決工作是否愈放愈久Average Age反映仍未解決工作年齡，不是完成工作的平均處理時間
已解決工作花多久Resolution Time看已 resolved 資料；不同於 board 所選欄位的 cycle time
這期 sprint 有多少剩餘Sprint Burndown／Sprint Health選正確 board、sprint；先確認估算與完成判定
哪些內容最近變動Activity Stream適合追動態；事件數不是完成工作量
到期日與 release 日程Issue Calendar／Road MapCalendar 依站台可用 gadgets／相關 app；Road Map gadget 看版本，不等於 Plans

Gadget 目錄中的舊稱 issue 可能已改成 work item。可用項目依 app、站台與方案設定不同，先看 Add gadget 的實際清單。內建無法滿足需求時，先確認資料定義，再評估 app；不要一看到沒有選項就假定資料不存在。

新使用者的第一頁：先區分介紹、探索、個人待辦與統計

Introduction提供導覽說明；Projects協助探索可見專案；Labels依可見資料提供標籤入口；Activity Stream顯示可見範圍的近期活動。這些用途不必以「已有指派給我的工作」為前提，但仍受權限、實際內容及 gadget 是否可用影響。不能保證剛建立帳號就一定有活動或標籤。

Assigned to Me、Issues in Progress、Watched Issues則需要對應的個人資料：有人指派給我、我有進行中的工作、或我已關注工作。新使用者看見空清單，未必是 dashboard 設壞。特別是 Issues in Progress 是個人工作清單，不能直接當成指定團隊所有進行中工作的總數。

若需求是「指定 filter 的工作依負責人各有幾件」，用 Issue Statistics；要看單一維度比例，可用 Pie Chart；要交叉看負責人與狀態，選 Two Dimensional Filter Statistics。先讓 saved filter 定義團隊與進行中範圍，再選統計維度；不是選到名字有 In Progress 的 gadget 就完成需求。

原創反例：主管要看所有人進行中件數，新同事只要找自己的工作，能共用同一種 gadget 嗎？

主管可用團隊 filter 加 Issue Statistics，以 Assignee 分組；新同事可用個人清單。兩者都有「工作」但決策不同：前者需要集合與總數，後者需要逐張操作。不要把個人清單的顯示筆數當成團隊完整統計。

3．建立、配置與維護

由 Dashboards → Create dashboard，輸入「ACP620 訂餐團隊早會」，描述寫明資料範圍、未完成定義與使用情境。初次建立先維持私人，在 demo 驗證後再設定適合的 viewers／editors。

  1. 決定版面：選兩欄。左欄用較寬的 Filter Results 便於閱讀工作名稱，右欄放統計。
  2. 新增 gadget：進入 Edit → Add gadget，必要時 Load all gadgets，再新增所需元件。
  3. 指定來源：Filter Results 選「ACP620 JQL Lab」；選欄位與筆數，儲存 gadget 設定。不要把只顯示10筆當成只有10筆資料。
  4. 加入對照：Two Dimensional Filter Statistics 使用同一 filter，選 Assignee 與 Status，才能和清單比對。
  5. 檢查分享：在 Rename or share 設定 viewers／editors，並另外確認 filter sharing。需要分享的 global permission，見 620.3.1。
  6. 安排更新：手動 Refresh 可立即重查；若有 Configure automatic refresh，設定符合用途的分鐘頻率。更新頻率不會改變資料權限。

要以現有配置起步可 Copy dashboard；加入星號只是方便在自己的導覽找到它。Wallboard 適合持續顯示，Slideshow 可輪播多個已建立的 dashboard。顯示在電視上的資料仍要考慮現場觀眾；wallboard 不是額外資料授權。

4．三個分享層次，逐層排錯

現象先查理由
對方找不到整個 dashboardDashboard viewers、連結、登入帳號先能開啟容器
Dashboard 開了但某個 gadget 報 filter 無權限該 saved filter 的 View 分享Dashboard 與 filter 是不同物件
Gadget 有資料，但少於 ownerBrowse Projects、issue security、team-managed access資料可見性仍逐人檢查
相同權限仍有不同工作清單currentUser()、Assigned To Me 等動態來源每個 viewer 的「我」不同
新卡沒有立刻出現gadget 範圍、排序、顯示筆數與 refresh先排除設定與更新時點
無法改 gadgetdashboard 編輯權／owner、目前是否 Edit 模式能看不等於能編輯

檢查順序是：同事能否開 dashboard → 能否單獨執行 filter → 能否直接開某張缺少的 issue → query 是否含使用者函式 → gadget 配置與更新。應用 最小必要權限，不要為了讓圖有數字就授予全站管理員。

同一個 dashboard，兩個人看到不同數字的排查順序

先確認能開啟 dashboard，再確認 gadget 引用的 filter 是否分享給對方，最後以對方身分核對 Browse Projects／Browse spaces 與工作層級安全性。Dashboard 分享只授權看版面，不會自動分享 filter；filter 分享也不會額外授權讀取底層工作。兩人都能開啟且不報錯，仍可能因 issue security 或個人化條件而看到不同集合。

原創例：共用 filter 是assignee = currentUser()，甲看到甲的工作、乙看到乙的工作是正常行為。若 filter 完全不含個人化條件，仍要查資料權限、更新時間、gadget 設定與顯示上限，不能先認定計算錯誤。

5．互動選型：一句需求，有三種不同答案

先問使用者要「名單」、「分類數量」還是「隨時間變化」，再展開對應方案。

早會要直接點開每張未指派 Bug

用 Filter Results：project = FOOD AND issuetype = Bug AND assignee IS EMPTY AND statusCategory != Done。顯示 Key、Summary、Priority、Created。Pie Chart 只能告訴你分布，不方便逐張處理。

主管要看每位負責人在各狀態有幾件

用 Two Dimensional Filter Statistics，以固定 project filter 分成 Assignee × Status。不要使用 assignee = currentUser() 當來源，否則主管只看到自己的切片。

主管問「我們是不是一直清不完新需求」

用 Created vs Resolved，固定資料範圍及時間區間，再核對 unresolved 集合是否變大。單一時間點 Pie Chart 看不出流入／流出趨勢；若 Resolution 設定錯，先修資料流程再判斷產能。

6．Demo lab：以同一份資料驗證兩個 gadgets

延續上一節三筆含 acp620-jql-lab 的測試卡。先把 filter 改成 project = 你的key AND labels = acp620-jql-lab，不加 currentUser()。這個修改只套用自己建立的練習 filter。

步驟預期結果
建立私人 dashboard，加入 Filter Results；顯示至少3筆看到 A、B、C，與直接執行 filter 相同
加入 Two Dimensional Filter Statistics，選 Assignee × Status能以狀態與負責人交叉比對三張卡；空 Assignee 形成未指派類別
只把 B 由 To Do 改成 In Progress，重新整理B 在清單狀態改變，交叉表相應格數移動；總工作數仍3
另存一份含 assignee = currentUser() 的 filter，替換其中一個 gadget該 gadget 只顯示目前使用者的工作，另個仍是完整練習集合
若有已授權的一般測試帳號，分別測 dashboard 與 filter 的分享能區分容器分享與來源分享；不要公開給 Anyone 作為測試捷徑

完成後記錄 dashboard 名稱、filter ID、來源 JQL、資料口徑與配置截圖。不要調整全站 default dashboard；它會影響其他使用者。現行 UI 刪除個人 dashboard 可能用 Move to trash，確認對象後再清理，保留練習也可。

7．原創情境題與逐項解析

1．要看「每個 Assignee × 每個 Status 的件數」，選？

  1. Two Dimensional Filter Statistics
  2. Activity Stream
  3. Assigned To Me
查看答案與逐項解析

A。A 是雙維度交叉表；B 是活動事件；C 只看檢視者被指派的工作，回答不了全團隊分布。

English version

Show counts for every Assignee and Status combination. Choose a gadget.

  1. Two Dimensional Filter Statistics
  2. Activity Stream
  3. Assigned To Me

A. A creates a cross-tabulation. B shows events. C focuses on the viewer rather than the whole team.

2．Dashboard 分享成功，filter gadget 仍顯示無存取權，下一步？

  1. 把 dashboard 再分享一次
  2. 檢查來源 filter 的分享
  3. 修改每張卡 Summary
查看答案與逐項解析

B。A 未處理來源物件；B 找到不同分享層次；C 與存取權無關。

English version

Dashboard sharing works, but its filter gadget reports no access. Next step?

  1. Share the dashboard again
  2. Check the source filter sharing
  3. Change every issue summary

B. A does not address the source object. B checks its separate permissions. C is unrelated to access.

3．Pie Chart 顯示某人有一半工作，能推論他承擔一半工時嗎？

  1. 一定可以
  2. 不能，件數與工時不等同
  3. 改成三欄就可以
查看答案與逐項解析

B。A 把不同單位混在一起；B 正確，應看估時或 workload 資料；C 只改版面，不改統計定義。

English version

A pie chart shows one person owns half the items. Does that prove half the effort?

  1. Always
  2. No: item count is not effort
  3. Yes, after switching to three columns

B. A mixes units. B recognizes that estimates or workload data are needed. C changes layout, not the measurement.

4．要讓兩位同事各自看到自己的未完成工作，適合？

  1. Assigned To Me
  2. 固定 assignee = 某主管的 filter
  3. 公開分享給所有人
查看答案與逐項解析

A。A 隨 viewer 身分變化；B 固定另一個人；C 是分享範圍，沒有改查詢語意。

English version

Each colleague should see their own unfinished assignments. Choose.

  1. Assigned To Me
  2. A filter fixed to one manager as assignee
  3. Public sharing

A. A evaluates for each viewer. B is fixed to someone else. C changes sharing, not query meaning.

5．舊工作一直未解決，想知道 backlog 是否老化，用？

  1. Average Age
  2. Resolution Time
  3. Days Remaining in Sprint
查看答案與逐項解析

A。A 看未解決工作的年齡；B 看已解決所花時間；C 只告訴 sprint 剩幾天。

English version

Old unresolved items are accumulating. Which gadget measures backlog aging?

  1. Average Age
  2. Resolution Time
  3. Days Remaining in Sprint

A. A measures age of unresolved items. B measures resolved items. C measures time left in the sprint.

6．把 dashboard 加星號有什麼效果？

  1. 授予所有同事 Browse Projects
  2. 方便自己找到 dashboard
  3. 讓資料每分鐘更新
查看答案與逐項解析

B。A 與權限無關；B 是個人導覽便利；C 應在 refresh 配置設定。

English version

What does starring a dashboard do?

  1. Grants everyone Browse Projects
  2. Makes it easier for you to find
  3. Refreshes it every minute

B. A is unrelated to permissions. B describes personal navigation. C requires a refresh setting.

7．Filter Results 顯示10筆，filter 搜尋有37筆，首先？

  1. 認定資料消失
  2. 檢查 gadget 顯示筆數、排序與分頁
  3. 新增另一個 project
查看答案與逐項解析

B。A 缺乏依據；B 可區分顯示限制與集合大小；C 不會修正顯示設定。

English version

Filter Results displays 10 items, while the filter search finds 37. Check first?

  1. Assume data has disappeared
  2. Display limit, sorting and pagination
  3. Create another project

B. A is unsupported. B separates display limits from the full result set. C cannot fix gadget configuration.
